# 신호 흐름도는 anatomy가 아니라 데이터에서 그린다

방송 시스템 문서에 시각화를 더하면서 anatomy skill(손으로 짠 isometric SVG 그림)을 들였지만, 방송실 전체의 신호 흐름도에는 쓰지 않는다. 신호 흐름도는 장비·연결 데이터 모듈 하나에서 React Flow로 그리고, 배치는 빌드 시점에 elkjs로 계산한다. 생김새는 anatomy의 시각 언어(종이색, 톤 위계, `lit` 강조, 카드 틀)를 따른다. anatomy는 바뀌지 않는 원리(CG 출력 원리)와 구성이 안정된 공간(배치도)에만 쓴다.

방송실 구성은 아직 미확인이 많고 장비도 계속 늘어난다. 장비 하나를 더할 때 데이터 한 곳만 고치면 장비 목록표와 신호 흐름도가 함께 바뀌어야 한다. anatomy 그림은 부품·케이블 경로를 손으로 짜고 `--audit`으로 증명해야 품질이 나오므로, 데이터에서 자동으로 만들면 밋밋한 상자가 되거나(skill이 거부하는 "too flat and bland") 케이블 자동 경로 문제를 풀어야 한다.

## Considered Options

- **React Flow 기본 모양** — 가장 빠르지만 anatomy 그림들과 따로 논다.
- **데이터에서 isometric 그림 생성** — 위의 이유로 기각.
- **모두 확정된 뒤 전체를 anatomy로 손수 그리기** — 확정을 기다리는 동안 그림이 없다. 방송실 구성이 안정되면 개요용 그림으로 따로 더할 수 있으니 버리지 않는다.
