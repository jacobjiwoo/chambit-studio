## 건드리지 않는 것

04가 `app/docs/broadcast-system/`의 `layout.tsx`·`page.mdx`·`_lib`를 만든다. 이 티켓은 `glossary/`·`equipment/` 폴더와 `.scratch/broadcast-system/upgrade-proposals.md`만 만든다. 04가 아직 머지되지 않았으면 페이지는 사이드바 없이 루트 레이아웃으로 보이는 것이 맞다.

## 원래 파일 받기

원래 파일은 저장소에 없다. Claude 프로젝트 문서(Projects 도구로 읽는다)이거나 사람이 건넨다. **걸러 내기 전의 원래 파일을 저장소 안에 두지 않는다** — 작업 복사본은 저장소 밖에 둔다. public 저장소라 한 번 커밋하면 히스토리에서 지울 수 없다.

## 걸러 내기

- 내부 네트워크 주소를 지운다(예: LED 프로세서 IP).
- 선임 설명을 평가한 문장을 바꾼다. 장비 목록표의 "온라인 송출 신호 흐름" 절에 있는 "의심", "절반만 맞음" 같은 판단은 사실(선임 설명의 내용, 확인된 것)과 미확인(`<Unconfirmed>`)만 남긴다. 설명이 사실과 다를 수 있는 근거(예: 일반 HD-SDI 케이블 가격)는 평가가 아니라 확인할 거리로 적는다. 업그레이드 제안의 문제 진단은 장비 구조에 대한 것이라 그대로 둔다.
- 그 밖에 공개가 걸리는 것을 발견하면 바꾸지 말고 Answer에 목록으로 적어 사람에게 묻는다.

## 옮기는 규칙

- 내용은 바꾸지 않는다. 걸러 내기와 아래 형식 변환만 한다.
- 원래 파일 맨 앞의 "최종 수정·근거·표기 규칙" 머리는 frontmatter(`title`, `description` 150자 이내, `slug`, `order`)와 본문 첫 문단으로 바꾼다. 순서는 용어집 1, 장비 목록표 2.
- "확인 필요"를 `<Unconfirmed>`로 바꾼다. 미확인인 것을 감싼다(예: "출발 장비 확인 필요" → `<Unconfirmed>출발 장비</Unconfirmed>`). 감쌀 대상이 분명하지 않으면 `<Unconfirmed />`로 두고 Answer에 적는다. "추정"·"선임 설명"·"사용자 확인"은 글자 그대로 둔다.
- 표 칸의 `<br>`은 MDX에서 `<br />`로 바꾼다.
- 장비 목록표의 "확인 필요 목록"은 그대로 둔다(자동 수집은 map의 Fog).
- 문서 사이 참조(예: "90_업그레이드_제안.md 1번 참고")는 새 위치로 고친다. 사이트 페이지에서 업그레이드 제안을 가리킬 때는 사이트 밖(GitHub)이라는 것이 드러나게 쓴다.

## Claude 프로젝트 정리

옮긴 뒤 Claude 프로젝트의 원래 파일 셋을 "저장소로 옮겼다"는 안내(저장소 경로, 날짜)로 바꾼다. 사람이 확인한 뒤에 한다.

## 끝난 조건

- 두 페이지의 표와 배지가 깨지지 않는다(빌드한 HTML에서 확인). 사이드바 순서는 05에서 본다.
- Answer에 `### 걸러 낸 것`(원래 문장 요지 → 바꾼 것), `### Unconfirmed로 못 감싼 곳`, `### 사람에게 물을 것` 표를 둔다. 원래 문장을 그대로 옮겨 적지 않는다 — 걸러 낸 내용이 Answer로 커밋되면 걸러 낸 의미가 없다.
- 사람이 걸러 낸 결과를 확인한다.
- `pnpm lint`, `pnpm typecheck`, `pnpm build`가 통과한다.

## Answer

원래 파일 셋을 걸러 내 옮겼다. 원래 파일은 채팅으로 받았고 저장소 안에 두지 않았다. 사람 확인 전이라 Status는 그대로 둔다.

- [`glossary/page.mdx`](../../../app/docs/broadcast-system/glossary/page.mdx) — 걸러 낼 것이 없었다. 첫 문단의 "방송부 핸드북"만 "방송 시스템 문서"로 바꿨다(문서 사이 참조).
- [`equipment/page.mdx`](../../../app/docs/broadcast-system/equipment/page.mdx) — 머리를 frontmatter와 첫 두 문단으로 바꾸고, 파일 번호("01.")를 H1에서 뺐다. "00_용어집 기준"은 용어집 페이지 링크로, "90_업그레이드_제안.md 1번"은 GitHub의 `upgrade-proposals.md` 링크와 "사이트 밖 작업 문서" 안내로 바꿨다.
- [`upgrade-proposals.md`](../upgrade-proposals.md) — 내용은 그대로 두고 H1의 파일 번호를 뺐다. 용어집·장비 목록표 위치를 머리 목록에 한 줄 더했다.
- 형식 변환: 표 칸 `<br>` → `<br />`. 범위를 뜻하는 `~`는 `\~`로 이스케이프했다. `remark-gfm`은 한 줄에 `~`가 둘이면 취소선으로 만든다(예: 영상 스위처 행의 입력·출력 범위). GitHub도 같아서 `upgrade-proposals.md`에도 적용했다.
- 빌드한 HTML 확인: 장비 목록표 표 7개, 행 53개(원래 행 수와 같다), `<del>` 0개, IP 형태 문자열 0개, 날것의 `<Unconfirmed` 문자열 0개. H2 앵커 11개가 생겼다.

### Unconfirmed로 못 감싼 곳

감쌀 글자가 없는 곳은 `<Unconfirmed />`로 두었다.

| 위치 | 이유 |
| - | - |
| 장비 목록표의 칸 전체가 "확인 필요"였던 곳(제조사·모델명, 위치, 연결 칸) — 음향 파워 컨디셔너 연결, 영상 hub 모델·위치, 멀티뷰·구형 카메라 컨트롤러·CAM3·CAM4·CAM5·CAM6·CG PC·방송실 TV·DVD 레코더 모델, 방송실 스피커 모델·연결 | 칸 값 자체가 비어 있다. 감쌀 대상이 없다 |
| 오디오 분배기 입력, CD/USB 플레이어 도착 장비 | 같은 이유. 뒤의 "추정" 괄호는 글자로 남김 |
