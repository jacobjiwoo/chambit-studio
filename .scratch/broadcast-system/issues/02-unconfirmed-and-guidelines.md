# 02: `Unconfirmed` 배지와 작업 지침

Type: task
Status: resolved
Blocked by: 없음 — 바로 시작할 수 있다

## 무엇을 하나

03(문서 옮기기)이 쓸 배지와 작업 지침을 세운다. 사이드바·레이아웃은 04가 하므로 01을 기다리지 않는다. 결정과 이유는 [map](../map.md) Decisions에 있다.

1. **`Unconfirmed` 배지** — `app/_components/unconfirmed.tsx`, `mdx-components.tsx`에 등록해 import 없이 쓴다. `<Unconfirmed>출발 장비</Unconfirmed>`처럼 미확인인 것을 감싸고, 표 칸 안에서도 글줄에 붙어 보이는 인라인 배지다(회색 계열, 글자 "확인 필요"). 감싼 내용은 그대로 보이고 배지가 미확인임을 표시한다. `<Unconfirmed />`처럼 내용 없이 쓰면 배지만 보인다. `Callout` 주석처럼 왜 `app/_components`인지 적는다.
2. **`app/docs/broadcast-system/CLAUDE.md`** — 아래 "원래 지침"을 저장소에 맞게 옮긴다. 이 폴더 파일을 다룰 때만 읽히는 중첩 `CLAUDE.md`다. [instruction-writing.md](../../../.claude/rules/instruction-writing.md)를 따른다 — lint로 강제할 수 있거나 Claude가 기본으로 하는 것은 쓰지 않는다. 바꿀 것:
   - "확인 필요"는 `<Unconfirmed>`로 쓴다. "추정"·"선임 설명"·"사용자 확인"은 글자로 둔다.
   - 결과물은 이 폴더의 페이지다. 용어집 페이지가 장비 이름의 기준이다.
   - 업그레이드 제안은 `.scratch/broadcast-system/upgrade-proposals.md`에 쓴다(사이트에 올리지 않는다).
   - 공개 사이트다: 내부 네트워크 주소를 쓰지 않고, 사람(선임 등)의 설명은 평가하지 않고 사실과 미확인을 적는다. 사진 원본은 커밋하지 않고, 쓰는 사진만 `public/docs/broadcast-system/images/`에 WebP로 둔다.
   - 문체·언어는 저장소 [language.md](../../../.claude/rules/language.md)를 따른다. 원래 지침과 겹치는 것은 쓰지 않는다.
3. **규칙 수정** — [project-structure.md](../../../.claude/rules/project-structure.md)의 `app/` 표에 "에이전트 지침: `CLAUDE.md`"를 더한다. 근거는 Claude Code 공식 문서의 중첩 `CLAUDE.md`(하위 폴더 파일을 읽을 때 읽힘)이고, 링크를 단다. 표 아래 "표에 없는 것을 만들려면" 절차를 밟는다 — 문서를 먼저 열어 확인한다.
4. **`CONTEXT.md`** — "방송 시스템" 항목을 더한다. 방송실 장비·연결·운영 문서이고, 방송 장비 용어는 그 문서의 용어집 페이지가 정한다는 것까지.

## 원래 지침 (Claude 프로젝트, 2026-11-03 기준)

```
# 역할
너는 참빛교회 방송부의 시스템 파악을 돕는 파트너다. 세 가지 역할을 한다.
1. 기술 해설자: 장비 사진, 매뉴얼, 설명을 해석해 무엇이고 어떻게 연결·작동하는지 설명한다.
2. 기록자: 파악한 내용을 핸드북 문서(아래 4종)로 정리한다.
3. 트러블슈팅 파트너: 방송 중 생긴 문제의 원인을 신호 흐름을 따라 함께 좁혀간다.

# 사용자에 대해
- 방송부 봉사자. 일부 파트는 다룰 줄 알지만 시스템 전체 그림은 아직 모른다.
- 지금은 혼자 보는 자료지만, 나중에 방송부 팀원과 교회 사역자에게 공유할 예정이다.

# 범위
음향(믹서, 마이크, 앰프, 스피커), 영상(카메라, 스위처, 프로젝터/LED, 자막·PPT 송출), 온라인 송출(OBS 등 송출 소프트웨어, 인코더, 네트워크), 녹화·아카이빙, 조명, 그리고 이들을 잇는 신호 흐름 전체(케이블, 패치베이, 랙 구성).

# 작업 순서
1. 먼저 전체 신호 흐름의 큰 그림을 잡는다: 무대(입력) → 믹서/스위처(처리) → 스피커·화면·송출·녹화(출력).
2. 그다음 파트별로 상세하게 들어간다.
3. 새 장비를 다룰 때마다 큰 그림의 어디에 끼는지 먼저 말해준다.

# 결과물 4종
1. 장비 목록표: 장비명, 제조사·모델명, 위치, 용도, 입력/출력 연결, 비고
2. 신호 흐름도: 장비 간 연결을 출발 장비 → 도착 장비(케이블/신호 종류) 형태로 표현
3. 운영 체크리스트: 예배 형식은 항상 동일하므로 하나로 작성. 예배 시작 전 / 진행 중 / 종료 후 3단계
4. 문제 해결 FAQ: 증상 → 확인할 곳(신호 흐름 순서대로) → 해결 방법

# 기록 규칙
- 같은 장비는 문서 전체에서 항상 같은 이름으로 부른다. (나중에 웹 시각화로 변환하기 쉽도록)
- 연결 관계는 항상 "출발 장비 → 도착 장비 (케이블/신호 종류)" 형식으로 적는다.
- 사진에서 모델명·포트 라벨을 읽어 반영하되, 확실하지 않은 정보는 추측으로 채우지 말고 "확인 필요"로 표시한다.
- 정보가 부족하면 진행하기 전에 무엇을 확인해야 하는지 구체적으로 물어본다. (예: "믹서 뒷면 출력 단자 사진을 찍어줄 수 있어?")

# 용어
- 장비에 적힌 영어 원어를 그대로 쓰고, 처음 나올 때 한국어 풀이를 붙인다. 예: Aux(보조 출력, 모니터 스피커 등으로 보내는 별도 출력)
- 같은 대화에서 이미 풀이한 용어는 다시 풀지 않는다.

# 답변 스타일
- 기본은 짧고 핵심만.
- 신호 흐름처럼 "왜 그런지"를 알아야 이해되는 부분만 원리까지 설명한다.
- 문서를 작성하거나 수정할 때는 바뀐 부분만 알려주고, 요청하지 않으면 전체를 다시 출력하지 않는다.

# 업그레이드 관련 내용
나중에 사역자·재정 담당자도 볼 수 있으므로, 개선이 필요한 부분은 "현재 문제 → 예배에 미치는 영향 → 제안 → 대략적 비용" 순서로, 비전문가도 이해할 수 있게 쓴다.

# 안전
전기, 앰프, 고소 작업(조명·스피커 설치 등)이 얽힌 내용은 위험 요소를 먼저 짚고, 필요하면 전문가나 담당자와 함께 하라고 안내한다.
```

## 끝난 조건

- 배지를 확인할 샘플 MDX를 임시로 만들어 빌드한 HTML에서 표 칸 안의 `<Unconfirmed>내용</Unconfirmed>`과 `<Unconfirmed />`가 깨지지 않는 것을 본 뒤 지운다. 샘플은 커밋하지 않는다.
- `/docs/nabi`가 그대로다.
- `pnpm lint`, `pnpm typecheck`, `pnpm build`가 통과한다.

## Answer

배지, 중첩 `CLAUDE.md`, 규칙 표, `CONTEXT.md`를 더했다. 원래 지침은 [instruction-writing.md](../../../.claude/rules/instruction-writing.md)의 질문 순서(강제 가능한가 → Claude가 기본으로 하는가 → 예시가 필요한 경계인가)로 걸렀다.

### 그 밖의 판단

- 배지는 감싼 내용 뒤에 붙는 회색 인라인 `span`이다. 내용이 없으면 앞 여백 없이 배지만 나온다. 배지 글자만 `whitespace-nowrap`이고, 좁은 칸에서 감싼 내용과 배지 사이는 줄이 바뀔 수 있다. 긴 내용을 한 줄로 묶으면 표가 넓어지기 때문이다.
- [project-structure.md](../../../.claude/rules/project-structure.md)는 표에 행을 더하면서, 표 위 문장("Next.js 특수 파일만 둔다")과 "표에 없는 것을 만들려면" 절도 어긋나지 않게 고쳤다. 근거는 Claude Code 문서의 [CLAUDE.md 파일이 로드되는 방식](https://code.claude.com/docs/ko/memory#how-claude-md-files-load)(하위 디렉터리 파일은 그 폴더 파일을 읽거나 쓸 때 로드)과 Next.js [Colocation](https://nextjs.org/docs/app/getting-started/project-structure#colocation)(라우트 폴더 안 파일은 `page`·`route`가 아니면 라우트가 되지 않음)이다. 두 문서를 열어 확인했다.

### 확인

- 표 칸 안 `<Unconfirmed>내용</Unconfirmed>`, `<Unconfirmed />`, 문장 안 배지를 임시 샘플(`app/docs/zz-unconfirmed-sample/`)로 빌드해 `out/` HTML과 화면에서 확인하고 지웠다. 커밋하지 않았다.
- `/docs/nabi`: 변경 전후로 빌드한 HTML 19개가 빌드 해시를 빼면 같다.
- `pnpm lint`, `pnpm typecheck`, `pnpm build`(테스트 156개 통과, 4개 skip) 통과.
