# 방송 시스템 문서

Label: `wayfinder:map`

> 이 문서를 다루는 에이전트는 먼저 [`app/docs/broadcast-system/CLAUDE.md`](../../app/docs/broadcast-system/CLAUDE.md)를 읽는다(티켓 [02](issues/02-unconfirmed-and-guidelines.md)가 만든다). `.scratch/`는 그 폴더 밖이라 자동으로 읽히지 않는다.

## Destination

참빛교회 방송실 전체(장비, 연결, 운영)를 다루는 문서가 `/docs/broadcast-system` 아래 MDX 페이지로 있다. 사이트 이름은 "방송 시스템"이고, 메인 화면 도구 목록에서 들어간다. 이 저장소가 문서의 유일한 원천이고, 이후 장비 조사와 정리도 여기서 한다.

## Notes

**원래 Claude 프로젝트에서 쓰던 "방송부 시스템 핸드북"이다.** 방송실 사진·매뉴얼·선임 설명을 해석해 문서로 정리해 왔다. 옮기는 시점(2026-11-03)에 있는 문서는 셋이다.

| 원래 파일 | 무엇 | 옮길 곳 |
| - | - | - |
| `핸드북/00_용어집.md` | 방송부 공식 용어 | 사이트 페이지 |
| `핸드북/01_장비목록표.md` | 장비별 모델·위치·용도·연결, 온라인 송출 신호 흐름, 확인 필요 목록 | 사이트 페이지 |
| `핸드북/90_업그레이드_제안.md` | 문제 → 영향 → 제안 → 비용 | `.scratch/broadcast-system/upgrade-proposals.md` (사이트에 올리지 않음) |

신호 흐름도, 운영 체크리스트(예배 전 / 중 / 후), 문제 해결 FAQ는 아직 없다. 쓰면 페이지로 더한다.

**원문은 저장소에 커밋하지 않는다.** 원래 파일에는 공개하지 않기로 한 내용(아래 Decisions의 걸러 내기)이 있다. public 저장소라 한 번 커밋하면 히스토리에 남는다. 걸러 낸 결과만 커밋한다.

**`/docs/nabi`와 다른 점** — NABI 매뉴얼은 외부 PDF를 원문 그대로 옮긴 완성본이다. 이 문서는 우리가 쓰고 계속 고치는 문서이고, "확인 필요"가 많다. 그래서 "확인 필요"를 숨기지 않고 보이게 한다.

## Decisions so far

- **경로는 `/docs/broadcast-system`, 사이트 이름은 "방송 시스템"이다.** "handbook"은 무엇을 다루는지 드러나지 않아 뺐다. `control-room`(방송실)은 본당 카메라·LED 스크린처럼 방송실 밖 장비를, `infrastructure`는 운영 체크리스트·FAQ를, `signal-flow`·`system-map`은 체크리스트를 빠뜨린다. "시스템"은 하드웨어 구조와 그 위의 운영을 둘 다 덮고, 원래 프로젝트 이름("방송부 시스템 핸드북")과도 이어진다.
- **공개 사이트에 올리되 옮기면서 걸러 낸다.** 내부 네트워크 주소(LED 프로세서 IP)는 지운다. 선임 설명을 평가한 문장("의심", "절반만 맞음")은 사실과 "확인 필요"만 남기는 중립 표현으로 바꾼다. 팀원·사역자에게 공유할 문서라 어차피 바꿀 표현이었다. Cloudflare Access는 기각했다 — 저장소가 public이라 GitHub에서 원문이 그대로 보인다.
- **저장소가 유일한 원천이다.** Claude 프로젝트의 원래 파일은 "저장소로 옮겼음" 안내로 바꾼다. 두 벌로 두면 반드시 어긋난다.
- **업그레이드 제안은 사이트에 올리지 않고 `.scratch/broadcast-system/upgrade-proposals.md`에 둔다.** 라우트로 두고 메뉴에서만 빼는 길은 기각했다 — 주소만 알면 열리는 공개 페이지라 "사이트에 안 둔다"는 뜻과 어긋난다. GitHub에서는 보인다.
- **용어집은 사이트 페이지다. `CONTEXT.md`에 합치지 않는다.** 독자가 다르다(방송부원 vs 코드 작업자). `CONTEXT.md`에는 "방송 시스템" 한 항목만 더한다.
- **지금은 MDX로 옮긴다.** 장비·연결을 데이터 파일로 빼서 렌더링하는 일은 신호 흐름도를 설계할 때 따로 정한다. 데이터 모양은 신호 흐름도가 무엇을 그려야 하는지 정해진 뒤에야 맞게 정할 수 있다. 장비 이름은 이미 용어집 기준으로 통일돼 있어 나중에 빼기 쉽다.
- **"확인 필요"는 전역 컴포넌트 `<Unconfirmed>…</Unconfirmed>` 배지로 보인다.** 무엇이 미확인인지를 감싸는 형태다. 그래야 나중에 미확인 목록을 자동으로 모을 수 있다. "추정"·"선임 설명"·"사용자 확인"은 글자 그대로 둔다 — 배지 종류가 늘면 독자가 범례를 외워야 한다. `Callout`처럼 `app/_components/`에 두고 `mdx-components.tsx`에 등록한다.
- **문서 하나 = 페이지 하나다.** 장비 목록표 안의 파트(전원, 영상·온라인 송출 등)는 H2 앵커로 나눈다. 방송실에서는 한 페이지 안 검색이 빠르다. 아직 없는 문서는 메뉴에 두지 않는다.
- **작업 지침은 `app/docs/broadcast-system/CLAUDE.md`에 둔다.** 전역 `.claude/rules/`가 아니라 이 문서 폴더의 중첩 `CLAUDE.md`라, 이 폴더 파일을 다룰 때만 읽힌다. `project-structure.md` 표에는 없던 파일이라 표에 근거(Claude Code 공식 문서)와 함께 더한다.
- **사진 원본은 커밋하지 않는다.** 페이지에 쓰는 것만 `public/docs/broadcast-system/images/`에 WebP로 넣는다. public 저장소라 방송실 내부 사진이 통째로 공개되고 용량도 크다.
- **티켓은 다섯이고 두 줄로 나란히 돈다.** 사이드바 공용화(01)를 따로 떼는 것은 NABI 매뉴얼 코드를 건드리는 리팩터라 회귀 확인을 분리하기 위해서다. 처음에는 넷을 한 줄로 두었으나, 뼈대 티켓에서 사이드바가 필요 없는 일(배지, 작업 지침)을 02로 떼어 레이아웃(04)과 나눴다. 문서 옮기기(03)는 배지와 지침만 있으면 되므로 01을 기다리지 않는다. 03은 사람 확인이 있어 가장 오래 걸리고, 그동안 01→04가 함께 진행된다. 동시에 도는 티켓끼리 같은 파일을 만지지 않도록 티켓마다 "건드리지 않는 것"을 적었다.
