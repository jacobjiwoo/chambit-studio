# 방송 시스템 시각화

Label: `wayfinder:map`

> 이 문서를 다루는 에이전트는 먼저 [`app/docs/broadcast-system/CLAUDE.md`](../../app/docs/broadcast-system/CLAUDE.md)와 [ADR 0001](../../docs/adr/0001-signal-flow-from-data.md)을 읽는다. 문서 자체의 결정은 [broadcast-system map](../broadcast-system/map.md)에 있다.

## Destination

`/docs/broadcast-system`에 방송실 구조를 그림으로 보이고 만질 수 있게 한다. 장비·연결은 데이터 모듈 하나가 원천이고, 장비 목록표·신호 흐름도·확인 필요 목록이 모두 거기서 나온다. 장비가 늘거나 미확인이 풀리면 데이터 한 곳만 고친다. 바뀌지 않는 원리와 안정된 공간은 anatomy skill로 공들여 그린다.

## Notes

**그림이 답할 질문은 셋이다.**

1. 큰 그림 익히기 — 입력 → 처리 → 출력이 어떻게 이어지나
2. 트러블슈팅 — 이 장비가 꺼지면 무엇이 끊기나, 증상이 나면 어디부터 보나
3. 원리 이해 — Fill/Key로 CG가 얹히는 방식 등

**그림은 두 종류다.** 둘은 다른 문서다.

- **신호 흐름도**: 장비와 장비 사이의 논리적 연결(SDI, XLR, HDMI…). 실제 자리와는 상관없다. 1·2를 맡는다.
- **배치도**: 영상 데스크·음향 데스크·랙 위에 장비가 실제로 어디 놓였나. 1을 맡고, 방송실에서 장비를 찾게 한다.

**anatomy skill** — `~/.claude/skills/anatomy` (https://github.com/wheresryan22/anatomy). 실물 하나를 부품 40–150개로 손수 짜는 isometric SVG다. MIT 라이선스라 `kit/`을 복사해 쓸 수 있고 라이선스 고지를 함께 둔다. React/Next.js에서는 정적 그림을 서버 컴포넌트로, 움직임을 `"use client"` 컴포넌트 하나로 나눈다(`references/react.md`).

## Decisions so far

- **모두 확정될 때까지 기다리지 않는다.** 바뀌는 것(장비, 연결)은 데이터에서 그리고, 굳은 것만 anatomy로 그린다. 확정되는 순서대로 anatomy 그림을 하나씩 더한다.
- **신호 흐름도는 데이터에서 React Flow로 그리고 생김새만 anatomy를 따른다.** [ADR 0001](../../docs/adr/0001-signal-flow-from-data.md). 모두 확정된 뒤 전체를 anatomy로 손수 그리는 개요 그림은 버리지 않고 Fog에 둔다.
- **데이터는 장비와 연결이다.**
  - 장비: `id`(용어집 이름), 파트(전원, 영상·온라인 송출…), 제조사·모델, 위치, 용도, 비고, `toConfirm: string[]`(확인할 거리)
  - 연결: 출발, 도착, 포트(선택), 신호 종류, 근거(사용자 확인·선임 설명·추정… 글자 그대로), 미확인 여부, `toConfirm`
  - 문장 중간의 `<Unconfirmed>`는 `toConfirm`으로 옮긴다. 그래야 확인 필요 목록을 데이터에서 모은다.
  - 포트는 선택이다. 뒷면 확인이 보류라 대부분 비어 있다.
- **데이터는 TypeScript 모듈이고 옆에 테스트를 둔다.** 연결의 양 끝이 실제 장비인지, 장비 `id`가 용어집 이름과 맞는지, 아무 연결에도 없는 장비가 있는지를 `pnpm test`가 잡는다. 봉사자가 직접 고치지 않고 에이전트와 함께 고치는 파일이라 타입의 이득이 크다.
- **배치는 빌드 시점에 서버 컴포넌트에서 elkjs로 계산한다.** 브라우저는 좌표를 받아 상호작용만 한다. `output: "export"`와 맞는다.
- **트러블슈팅 인터랙션은 단순하게 시작한다.** 장비를 누르면 하류 전체를 "영향 받을 수 있음"으로, 상류를 "여기부터 확인"으로 칠한다. 장비마다 필수 입력을 정하는 정밀 모델은 직렬 구조부터 미확인이라 미룬다. 데이터에 `required` 같은 필드를 나중에 더할 여지를 둔다.
- **미확인은 그림에서도 보인다.** anatomy 규칙상 점선은 쓰지 않으니 흐린 톤과 배지 아이콘으로 구분한다. 누르면 확인할 거리가 보인다.
- **anatomy 첫 그림은 CG 출력 원리다.** 문자발생기 보드 설정까지 확인됐고, 방송실 구성이 바뀌어도 원리는 같다. 온라인 송출 직렬 구조는 실물 확인(장비 목록표 확인 필요 3번) 뒤로 미룬다.
- **배치도는 공간마다 anatomy 그림 하나다.** 그림 속 장비에 데이터 `id`를 달아 누르면 장비 정보가 열린다. 모양은 손으로 그린다. 그 공간의 장비 구성이 안정된 뒤 그린다. 영상 데스크는 확인 필요 2번(영상 hub)과 3번(직렬 구조)이 풀린 뒤다.
- **페이지 배치.** 신호 흐름도는 새 페이지이고, 장비 목록표의 "온라인 송출 신호 흐름" 절이 그리로 옮겨 간다. CG 출력 원리 그림은 장비 목록표의 해당 절 안에 넣는다. 배치도는 나중에 새 페이지다.
- **데이터 모듈은 `app/docs/broadcast-system/_lib/system.ts`다.** 장비 `toConfirm`은 배지 자리를 정하려고 `{ cell, what }[]`로 넓혔고, 끝점은 `{ id, unit?, port? }` 또는 `{ unknown, candidates? }`다. 확인 필요 목록 대응표와 옮기며 찾은 어긋남 8건은 [01](issues/01-system-data.md) Answer·Comments에 있다.
- **anatomy kit 복사본은 `_lib/anatomy/`와 `_components/anatomy/`에 있다.** CG 출력 원리 그림이 이것으로 그려진다. lint 규칙 셋을 이 두 폴더에서만 껐고, 그림은 실제와 다른 점 셋을 캡션에 밝힌다. [04](issues/04-cg-output-figure.md) Answer.
- **확인 필요 목록은 데이터에서 모은다.** 우선순위 1–15는 `system.ts`의 `priorities` 표에 두고, 장비 `toConfirm` 항목과 연결에 `priority`를 단다. 장비 행 앵커는 `장비-<id>`다. 손 목록의 빈 곳을 메우려고 `toConfirm` 몇 개를 더했다. [03](issues/03-unconfirmed-list.md) Answer.
- **신호 흐름도는 위에서 아래로 흐르고 단계 필드를 두지 않는다.** 연결 방향만으로 입력 → 출력 순서가 나온다. 배지는 미상 끝점과 미확인 연결에만 단다. `?device=<id>`로 장비를 고른 채 연다. [02](issues/02-signal-flow-page.md) Answer.
- **신호 흐름도는 네 탭으로 나눈다: 영상 · 오디오 · 전력 · 네트워크·제어.** 연결 54개를 그림 하나에 그리면 영상·오디오·전력이 섞여 읽기 어려워서다. 한 페이지 안의 탭이고 전체 그림은 없앤다. 처음에는 영상 탭을 연다.
  - **연결마다 필수 필드 `layers`를 둔다.** `signal` 글자로는 분류할 수 없다. 54개 중 12개가 비어 있고, 같은 SDI에도 소리가 실린 것과 아닌 것이 섞인다. 필수라서 연결을 더할 때 빠뜨리면 타입 에러가 난다.
  - **소리는 오디오 임베더에서 영상과 합쳐지므로 그 뒤 구간은 영상·오디오 양쪽에 그린다.** 송출 PC → 공유기, 백업 송출 장비 → 공유기, 공유기 → 유튜브는 네트워크에도 그린다. 소리가 실리는지 근거가 없는 LED·TV 쪽 HDMI·동축 연결은 영상만이고, 확인 필요 항목은 늘리지 않았다.
  - **숨기는 필터가 아니라 탭마다 ELK로 따로 배치한다.** 필터는 빠진 선 자리에 빈 구멍이 남아서다. 빌드 때 네 번 계산하고, 그림에는 그 그림의 연결에 닿는 장비·외부 지점만 나온다. 연결 없는 장비 6대는 어느 그림에도 없고 장비 목록표에만 남는다.
  - **칠하기는 한 그림 안에서만 한다.** 다른 그림으로 넘어가는 영향(전기가 나가 송출이 끊기는 것 등)은 자세히의 "○○ 그림에서 보기" 링크로 따라간다.
- **선 위에 연결 인터페이스(SDI, HDMI, DVI…)를 글자로 단다.** 변환이 끼는 곳(DVI → HDMI 분배기 등)이 그림에서 바로 보여야 문제를 좁히기 쉬워서다. 2026-11-10.
  - **`signal`은 `system.ts`의 `signals` 목록 값만 받는다.** 같은 SDI가 "SDI", "HD-SDI", "SDI 1개"로 갈라져 있었다. 개수·HD-SDI·동축 같은 덧붙임은 `detail`로 옮겼고, 인터페이스가 아닌 "제어"는 `detail`로 내렸다. 단자 이름으로 정해지는 빈 칸(SDI IN5·6, LAN 포트, HDMI 분배기 출력, 안테나 RF)은 채웠다. 단자를 모르는 연결은 비워 둔다.
  - **색으로 나누지 않고 mono 글자로 쓴다.** anatomy 톤 위계에서 색은 색이 주제일 때만 쓴다. 글자는 선의 가장 긴 토막 가운데에 카드색 테두리로 얹고, 미확인이면 같은 자리에 `?`를 붙인다. 글자 없는 미확인 선은 전처럼 `?` 배지만 단다.
  - **ELK는 글자 자리를 비워 두지 않는다.** 영상 스위처 입력처럼 선이 몰린 곳은 글자가 붙어 보인다. 겹침이 문제가 되면 ELK edge label로 자리를 잡는 길을 본다.
  - **주소는 `?view=<탭>&device=<장비 id>`다.** `view` 없이 `device`만 있으면 탭 순서대로 그 장비가 나오는 첫 탭을 연다. 확인 필요 목록의 링크는 그대로 둔다. 탭을 바꾸면 새 탭에도 있는 장비는 고른 채로 두고, 고른 선은 푼다. 그림 전체가 보이게 맞춘다.
- **모델이 확정된 장비는 생김새를 anatomy 그림으로 보인다.** 2026-11-11. 봉사자가 방송실에서 장비를 알아보고, 앞면 구역과 뒷면 단자를 익히게 한다.
  - **WebGL로 돌려 보는 3D는 쓰지 않는다.** 뒷면에서 중요한 것은 단자 이름이 읽히는 것이고, 고정 시점 두 장(앞·뒤)을 버튼으로 넘기는 쪽이 더 잘 읽힌다. 처음에는 앞을 연다.
  - **근거는 제조사 공식 매뉴얼이다.** 출처(제목·판·URL·쪽)는 [device-manuals.md](device-manuals.md)에 적는다. PDF와 제조사 이미지는 커밋하지 않는다. 캡션에 실물을 단순화한 그림이라고 밝힌다.
  - **그림은 가능한 한 세밀하게, 설명은 이름만.** 단자와 구역에 매뉴얼의 영어 표기를 그대로 단다. 이름만으로 알 수 없는 곳에만 한국어 한 줄을 더한다. 앞면은 버튼을 실제 개수대로 그리고 설명은 구역 단위다. 누르거나 올리면 이름이 나오고 움직임은 없다.
  - **단자 목록은 그림 모듈에 두고 `system.ts`의 `port`와 테스트로 대조한다.** 그림이 있는 장비의 `port`가 매뉴얼에 없는 이름이면 `pnpm test`가 잡는다. `port`가 적힌 단자만 "○○가 꽂혀 있다"고 표시한다.
  - **매뉴얼만으로 모르는 구성은 비워 그린다.** 옵션 슬롯 등은 빈 채로 두고 `toConfirm`에 더한다. 매뉴얼과 데이터가 어긋나면 목록으로 보이고 승인받아 고친다.
  - **장비 목록표 행과 신호 흐름도 자세히의 "생김새 보기" 버튼이 같은 dialog를 연다.** 장비별 페이지는 만들지 않는다. 휴대폰 너비에서 단자 이름이 읽혀야 한다.
  - **AV-HS410 그림과 공통 틀이 들어갔다.** 틀은 `_lib/device-figure.ts`, 그림 모음과 단자 대조는 `_lib/device-figures.ts`다. 패널 기울기는 매뉴얼에 없어 추정이다. 페이지 크기가 장비마다 gzip 200KB쯤 늘어, 07 전에 그림을 늦게 받을지 정한다. [06](issues/06-device-figure-av-hs410.md) Answer.
  - **3종 먼저다: AV-HS410, RC-IP100, HELO Plus.** 나머지 18종은 3종을 본 뒤 정한다. 06을 끝내면 멈추고 사람이 실물과 비교한 뒤 07·08을 시작한다.

## Fog

- **전체 개요 anatomy 그림** — 방송실 구성이 안정되면 방송실 전체를 손수 그린 개요 그림을 더할지. ADR 0001의 버리지 않은 대안이다.
- **온라인 송출 직렬 구조 anatomy 그림** — 확인 필요 3번이 풀린 뒤. "백업 장비가 꺼지면 주 송출도 끊긴다"를 움직임으로 보일 수 있다.
- **정밀 영향 모델** — 장비별 필수 입력. 직렬 구조가 확인된 뒤 다시 본다.
- **운영 체크리스트·문제 해결 FAQ와 그림의 연결** — FAQ의 "확인할 곳"을 신호 흐름도 경로 강조로 열지.
