# 02: 신호 흐름도 페이지

Type: task
Status: claimed
Blocked by: 01

## 무엇을 하나

`/docs/broadcast-system/signal-flow`에 신호 흐름도 페이지를 세운다. 01의 데이터에서 그린다. 결정과 이유는 [map](../map.md) Decisions와 [ADR 0001](../../../docs/adr/0001-signal-flow-from-data.md)에 있다.

1. **의존성** — `@xyflow/react`와 `elkjs`를 들인다. 버전은 들이는 시점의 안정판을 고정한다.
2. **배치** — 서버 컴포넌트에서 빌드 시점에 elkjs layered 배치로 좌표를 계산해 클라이언트 컴포넌트에 넘긴다. 흐름 방향은 입력 → 처리 → 출력이다. 단계를 데이터에 넣어야 배치가 읽히면 01의 모듈에 필드를 더한다.
3. **생김새** — anatomy `kit/iso.css`의 색·톤 위계를 따른다. 장비는 `mid`, 선택한 장비와 경로만 `lit`, 미확인 연결·장비는 흐린 톤과 배지 아이콘(점선 금지). 카드 틀은 `Fig n`·제목·힌트·live readout. 밝은·어두운 테마 둘 다.
4. **인터랙션** — 장비를 누르면 하류 전체를 "영향 받을 수 있음", 상류를 "여기부터 확인"으로 칠하고 readout에 장비 이름·모델·확인할 거리를 보인다. 연결을 누르면 신호 종류·근거·확인할 거리를 보인다. 확대·이동. 휴대폰 폭에서 쓸 수 있어야 한다.
5. **페이지** — `signal-flow/page.mdx`(frontmatter `order`는 장비 목록표 다음). 장비 목록표의 "온라인 송출 신호 흐름" 절을 이 페이지로 옮기고, 장비 목록표에는 링크 한 줄을 남긴다.
6. **CLAUDE.md** — [작업 지침](../../../app/docs/broadcast-system/CLAUDE.md)의 결과물 표 "신호 흐름도" 행에 데이터에서 그린다는 것과 데이터 위치를 적는다.

## 건드리지 않는 것

- 장비 목록표에서는 "온라인 송출 신호 흐름" 절만 옮긴다. 03이 "확인 필요 목록" 절을, 04가 "CG 출력 원리" 절을 만진다.
- 하류·상류 계산은 연결을 따라가는 단순 탐색이다. 장비별 필수 입력 모델을 만들지 않는다.

## 끝난 조건

- 하류·상류 계산이 순수 함수이고 옆에 테스트가 있다. 직렬 구조(오디오 임베더 → 백업 송출 장비 → 백업 녹화기 → 송출 PC 캡처카드 → 송출 PC)에서 백업 녹화기를 고르면 송출 PC와 유튜브가 하류로 나온다.
- 빌드한 페이지를 데스크톱·휴대폰 폭, 밝은·어두운 테마로 캡처해 사람이 확인한다.
- `pnpm lint && pnpm typecheck && pnpm test`, `pnpm build`가 통과한다.
