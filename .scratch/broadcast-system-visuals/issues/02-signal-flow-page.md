# 02: 신호 흐름도 페이지

Type: task
Status: resolved
Blocked by: 01

## 무엇을 하나

`/docs/broadcast-system/signal-flow`에 신호 흐름도 페이지를 세운다. 01의 데이터에서 그린다. 결정과 이유는 [map](../map.md) Decisions와 [ADR 0001](../../../docs/adr/0001-signal-flow-from-data.md)에 있다.

1. **의존성** — `@xyflow/react`와 `elkjs`를 들인다. 버전은 들이는 시점의 안정판을 고정한다.
2. **배치** — 서버 컴포넌트에서 빌드 시점에 elkjs layered 배치로 좌표를 계산해 클라이언트 컴포넌트에 넘긴다. 흐름 방향은 입력 → 처리 → 출력이다. 단계를 데이터에 넣어야 배치가 읽히면 01의 모듈에 필드를 더한다.
3. **생김새** — anatomy `kit/iso.css`의 색·톤 위계를 따른다. 장비는 `mid`, 선택한 장비와 경로만 `lit`, 미확인 연결·장비는 흐린 톤과 배지 아이콘(점선 금지). 카드 틀은 `Fig n`·제목·힌트·live readout. 밝은·어두운 테마 둘 다.
4. **인터랙션** — 장비를 누르면 하류 전체를 "영향 받을 수 있음", 상류를 "여기부터 확인"으로 칠하고 readout에 장비 이름·모델·확인할 거리를 보인다. 연결을 누르면 신호 종류·근거·확인할 거리를 보인다. 확대·이동. 휴대폰 폭에서 쓸 수 있어야 한다.
5. **페이지** — `signal-flow/page.mdx`(frontmatter `order`는 장비 목록표 다음). 장비 목록표의 "온라인 송출 신호 흐름" 절을 이 페이지로 옮기고, 장비 목록표에는 링크 한 줄을 남긴다.
6. **CLAUDE.md** — [작업 지침](../../../app/docs/broadcast-system/CLAUDE.md)의 결과물 표 "신호 흐름도" 행에 데이터에서 그린다는 것과 데이터 위치를 적는다.

## 건드리지 않는 것

- 장비 목록표에서는 "온라인 송출 신호 흐름" 절만 옮긴다. 03이 "확인 필요 목록" 절을, 04가 "CG 출력 원리" 절을 만진다.
- 하류·상류 계산은 연결을 따라가는 단순 탐색이다. 장비별 필수 입력 모델을 만들지 않는다.

## 끝난 조건

- 하류·상류 계산이 순수 함수이고 옆에 테스트가 있다. 직렬 구조(오디오 임베더 → 백업 송출 장비 → 백업 녹화기 → 송출 PC 캡처카드 → 송출 PC)에서 백업 녹화기를 고르면 송출 PC와 유튜브가 하류로 나온다.
- 빌드한 페이지를 데스크톱·휴대폰 폭, 밝은·어두운 테마로 캡처해 사람이 확인한다.
- `pnpm lint && pnpm typecheck && pnpm test`, `pnpm build`가 통과한다.

## Answer

페이지는 `app/docs/broadcast-system/signal-flow/page.mdx`(order 3)다. 그래프와 하류·상류 계산은 `_lib/flow.ts`, 배치는 `_lib/flow-layout.ts`, 그림은 `_components/signal-flow-figure.tsx`(서버, 빌드 때 elkjs) → `_components/signal-flow.tsx`(클라이언트, React Flow)다. 의존성은 `@xyflow/react` 12.12.1, `elkjs` 0.12.1로 고정했다.

**`system.ts`는 고치지 않았다.** 단계(입력/처리/출력) 필드를 더하지 않았다. 연결 방향만으로 elkjs layered가 직렬 구조를 입력 → 출력 순서로 놓고, `flow-layout.test.ts`가 그 순서를 지킨다.

**정한 것**

- **흐름 방향은 위 → 아래다.** 왼쪽 → 오른쪽으로 놓으면 그림이 1860×546으로 납작해서 본문 폭에 맞추면 글자가 읽히지 않았다. 위 → 아래는 1357×1204라 본문 폭과 휴대폰 폭에 더 맞다.
- **미상 끝점은 연결마다 따로 점이다.** "미상"끼리 같은 장비라는 근거가 없어서다. 후보 장비로는 선을 잇지 않으니 하류·상류 탐색도 후보를 지나지 않는다.
- **하류·상류는 연결 방향만 따라간다.** 전원·제어 연결도 같이 따라가므로 PTZ 컨트롤러를 고르면 카메라 아래가 모두 "영향"이 된다. 페이지 본문에 이 한계를 적었다. 칠하는 선은 고른 장비나 하류에서 나가는 선과, 고른 장비나 상류로 들어오는 선이다(`tracedEdges`). 그래서 상류에서 하류로 곧장 가는 곁길(예: 백업 녹화기를 고를 때 영상 전원 시퀀서 → 공유기)은 칠하지 않는다.
- **미확인 배지는 미상 끝점과 미확인 연결에만 단다.** 장비의 `toConfirm`(모델, 위치 등)은 장비 대부분에 있어 배지를 달면 구분이 안 됐다. 장비를 누르면 카드 아래에 확인할 거리가 모두 보인다.
- **"영향"·"확인"은 같은 lit 테두리에 작은 글자 표지로 가른다.** anatomy 톤 위계에서 색은 색이 주제일 때만 쓰므로 빨강·파랑으로 나누지 않았다.
- **휠은 페이지를 내린다.** 확대는 버튼, 핀치, Ctrl+휠이다. 문서 페이지에서 휠이 그림을 확대하면 스크롤이 막힌다.
- **테마는 사이트처럼 `prefers-color-scheme`을 따른다.** 토큰 값은 anatomy `kit/iso.css`의 밝은·어두운 값을 `_components/signal-flow.css`에 옮겼다(출처 주석).

**장비를 고른 채로 여는 주소** — `/docs/broadcast-system/signal-flow?device=<장비 id를 URL 인코딩>`. 예: `?device=%EB%B0%B1%EC%97%85%20%EB%85%B9%ED%99%94%EA%B8%B0`(백업 녹화기). 그 장비를 배율 1로 가운데 두고 고른 상태로 연다. 장비를 누르면 주소의 `device`도 바뀐다(`history.replaceState`). 없는 id면 무시하고 전체를 보인다.

**01이 넘긴 방향 문제** — "인터넷 → 공유기 WAN"과 "공유기 → 유튜브"는 그대로 두었다. 둘 다 데이터 흐름 방향으로 읽으면 맞다(인터넷이 들어오고, 송출이 나간다). 유튜브의 상류에 인터넷이 들어와 "확인"으로 칠해지는 것도 트러블슈팅에 맞다.

## Comments

**사람이 볼 것** — `pnpm build` 뒤 `out/docs/broadcast-system/signal-flow.html`을 연다(정적 서버에서는 `signal-flow.html`로 직접 연다).

- 위 → 아래 방향이 큰 그림 익히기에 읽히는지. 전체 맞춤 배율에서는 글자가 작아 확대해야 읽힌다.
- 백업 녹화기를 눌러 송출 PC 캡처카드·송출 PC·공유기·유튜브가 "영향", 백업 송출 장비·오디오 임베더·영상 hub·영상 스위처 쪽이 "확인"으로 칠해지는지.
- 미확인 연결(예: 영상 hub → 멀티뷰)을 눌러 근거·확인할 거리가 보이는지.
- 장비 목록표의 "온라인 송출 신호 흐름" 절이 링크 한 줄이 되고 내용이 신호 흐름도 페이지로 빠짐없이 옮겨졌는지.
