# 01: 장비·연결 데이터 모듈과 장비 목록표 렌더링

Type: task
Status: claimed
Blocked by: —

## 무엇을 하나

[장비 목록표](../../../app/docs/broadcast-system/equipment/page.mdx)의 장비 표들을 데이터 모듈로 옮기고, 페이지는 그 데이터에서 표를 그린다. 결정과 이유는 [map](../map.md) Decisions에 있다.

1. **데이터 모듈** — `app/docs/broadcast-system/_lib/system.ts`. map의 장비·연결 모양을 따른다. 지금 표에 있는 장비와 "입력/출력 연결" 칸의 연결을 모두 옮긴다.
   - 장비 목록 밖의 끝점(건물 전원, 인터넷, 유튜브, 본당 조명, 교회 내 TV, 안테나 등)은 장비와 구분되는 **외부 지점**으로 둔다.
   - 출발이나 도착을 모르는 연결(예: 오디오 임베더 CH1·CH2의 출발 장비)은 지어내지 않는다. 끝점을 "미상"으로 두고 후보를 `toConfirm`에 적는다.
   - "추정", "선임 설명", "사용자 확인"은 연결의 근거 필드에 글자 그대로 둔다. 배지로 만들지 않는다.
   - 신호 흐름의 단계(입력/처리/출력)를 장비에 둘지는 02가 배치를 짜 보며 정한다. 지금 넣지 않는다.
2. **테스트** — `system.test.ts`. 연결의 양 끝이 장비나 외부 지점이거나 "미상"인지, 장비 `id`가 [용어집 페이지](../../../app/docs/broadcast-system/glossary/page.mdx)의 굵은 표제어 또는 장비 목록표에만 나오는 정식 이름과 맞는지, 아무 연결에도 없는 장비가 있으면 그 목록을 내는지 확인한다. 용어집에 없는 이름은 실패시키지 않고 허용 목록으로 명시한다(예: "영상 hub (가칭)").
3. **렌더링** — 파트별 표를 그리는 컴포넌트를 `app/docs/broadcast-system/_components/`에 두고 페이지가 `<EquipmentTable part="…" />`처럼 쓴다. 칸 안 미확인은 지금처럼 `<Unconfirmed>` 배지로 보인다. H2 앵커와 순서는 그대로다.

## 건드리지 않는 것

- 장비 목록표의 산문 절(송출 PC OBS 설정, CG 출력 원리, 온라인 송출 신호 흐름, 현황 메모, 확인 필요 목록)은 그대로 둔다. 02·03·04가 옮기거나 바꾼다.
- 표의 내용을 고치지 않는다. 옮기기만 한다. 옮기다 어긋남을 찾으면 고치지 않고 이 티켓 Comments에 적는다.

## 끝난 조건

- 빌드한 장비 목록표를 지금 `main`의 것과 나란히 놓고 장비·칸·배지가 빠짐없는지 사람이 확인한다. 배지 위치는 칸 안에서 바뀔 수 있다.
- 장비 목록표의 "확인 필요 목록" 15항목이 모두 데이터의 `toConfirm` 어딘가에 대응하는지 표로 남긴다(03이 쓴다).
- `pnpm lint && pnpm typecheck && pnpm test`, `pnpm build`가 통과한다.
