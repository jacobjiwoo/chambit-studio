# 01: 장비·연결 데이터 모듈과 장비 목록표 렌더링

Type: task
Status: claimed
Blocked by: —

## 무엇을 하나

[장비 목록표](../../../app/docs/broadcast-system/equipment/page.mdx)의 장비 표들을 데이터 모듈로 옮기고, 페이지는 그 데이터에서 표를 그린다. 결정과 이유는 [map](../map.md) Decisions에 있다.

1. **데이터 모듈** — `app/docs/broadcast-system/_lib/system.ts`. map의 장비·연결 모양을 따른다. 지금 표에 있는 장비와 "입력/출력 연결" 칸의 연결을 모두 옮긴다.
   - 장비 목록 밖의 끝점(건물 전원, 인터넷, 유튜브, 본당 조명, 교회 내 TV, 안테나 등)은 장비와 구분되는 **외부 지점**으로 둔다.
   - 출발이나 도착을 모르는 연결(예: 오디오 임베더 CH1·CH2의 출발 장비)은 지어내지 않는다. 끝점을 "미상"으로 두고 후보를 `toConfirm`에 적는다.
   - "추정", "선임 설명", "사용자 확인"은 연결의 근거 필드에 글자 그대로 둔다. 배지로 만들지 않는다.
   - 신호 흐름의 단계(입력/처리/출력)를 장비에 둘지는 02가 배치를 짜 보며 정한다. 지금 넣지 않는다.
2. **테스트** — `system.test.ts`. 연결의 양 끝이 장비나 외부 지점이거나 "미상"인지, 장비 `id`가 [용어집 페이지](../../../app/docs/broadcast-system/glossary/page.mdx)의 굵은 표제어 또는 장비 목록표에만 나오는 정식 이름과 맞는지, 아무 연결에도 없는 장비가 있으면 그 목록을 내는지 확인한다. 용어집에 없는 이름은 실패시키지 않고 허용 목록으로 명시한다(예: "영상 hub (가칭)").
3. **렌더링** — 파트별 표를 그리는 컴포넌트를 `app/docs/broadcast-system/_components/`에 두고 페이지가 `<EquipmentTable part="…" />`처럼 쓴다. 칸 안 미확인은 지금처럼 `<Unconfirmed>` 배지로 보인다. H2 앵커와 순서는 그대로다.

## 건드리지 않는 것

- 장비 목록표의 산문 절(송출 PC OBS 설정, CG 출력 원리, 온라인 송출 신호 흐름, 현황 메모, 확인 필요 목록)은 그대로 둔다. 02·03·04가 옮기거나 바꾼다.
- 표의 내용을 고치지 않는다. 옮기기만 한다. 옮기다 어긋남을 찾으면 고치지 않고 이 티켓 Comments에 적는다.

## 끝난 조건

- 빌드한 장비 목록표를 지금 `main`의 것과 나란히 놓고 장비·칸·배지가 빠짐없는지 사람이 확인한다. 배지 위치는 칸 안에서 바뀔 수 있다.
- 장비 목록표의 "확인 필요 목록" 15항목이 모두 데이터의 `toConfirm` 어딘가에 대응하는지 표로 남긴다(03이 쓴다).
- `pnpm lint && pnpm typecheck && pnpm test`, `pnpm build`가 통과한다.

## Answer

데이터는 `app/docs/broadcast-system/_lib/system.ts`, 테스트는 옆의 `system.test.ts`, 표는 `_components/equipment-table.tsx`다. 장비 목록표는 파트마다 `<EquipmentTable part="…" />`를 쓴다.

**데이터 모양** — map의 모양을 따르되 표를 그리느라 두 군데를 넓혔다.

- 장비의 `toConfirm`은 `string[]`이 아니라 `{ cell, what }[]`다. `cell`(`model`·`location`·`purpose`·`connections`·`notes`)이 배지가 붙을 칸이다. 03은 `what`만 모으면 된다. 우선순위를 넣는다면 이 객체에 필드를 더하면 된다.
- 연결의 `toConfirm`은 `string[]`다. 끝점은 `{ id, unit?, port? }` 또는 `{ unknown, candidates? }`다. `unit`은 한 행으로 묶인 장비 중 하나(`CAM5·CAM6`의 `CAM5`), `unknown`은 그 자리에 보일 말("미상", "하위 장비", "음향 소리"), `candidates`는 후보 장비 id다.
- 외부 지점: 건물 전원, 인터넷, 유튜브, LED 스크린, 교회 내 TV, 본당 조명, 안테나.
- 테스트가 지키는 것: 끝점이 장비·외부 지점·미상(후보는 장비)인지, 장비 id가 용어집 표제어나 허용 목록에 있는지(허용 목록이 낡으면 실패), id가 겹치지 않는지, 미확인 연결과 끝점이 미상인 연결에 `toConfirm`이 있는지, 연결 없는 장비가 정해진 목록(음향 파워 컨디셔너, NABI USB 동글, LED 스크린 전원 버튼, 연결 패널, 방송실 스피커, DVD 레코더)뿐인지.

**확인 필요 목록 15항목 ↔ `toConfirm`** (03이 쓴다)

"장비 X / 칸"은 장비 `toConfirm`, "연결 A → B"는 연결 `toConfirm`이다.

## Comments

**사람이 나란히 볼 것** — `pnpm build` 뒤 `out/docs/broadcast-system/equipment.html`과 `main`의 같은 페이지를 연다. 행 하나씩 장비명, 제조사·모델명, 위치, 용도, 연결, 비고의 글과 배지가 빠지지 않았는지 본다. 아래 "바뀐 모양"은 의도한 차이다.

**바뀐 모양** (내용은 그대로, 그리는 방식 때문에)

- 연결 칸은 그 장비가 끝점이거나 미상의 후보인 연결을 모두 보인다. 같은 연결이 양 끝 행에 나오고, 전에 한쪽 행에만 있던 줄이 다른 행에도 생긴다(예: 영상 스위처 행에 카메라·CG 입력 줄). 반대로 CG PC 행에는 FILL·KEY 줄이 없다. 끝점이 CG PC 문자발생기 보드라서 그 행에만 있다.
- 문장 중간의 배지는 그 칸 끝으로 갔다. 배지만 있던 칸(`<Unconfirmed />`)은 "제조사·모델", "연결"처럼 무엇을 확인할지 글이 붙는다.
- 연결 전체를 감싼 배지(예: `<Unconfirmed>전압조정기 → 음향 UPS 추정</Unconfirmed>`)는 "전압조정기 → 음향 UPS (전원, 추정) 연결 여부[확인 필요]"가 된다.
- LED 프로세서의 "입력 출발 장비" 배지는 비고 칸에서 연결 칸(미상 → LED 프로세서 HDMI1)으로 옮겼다. 오디오 분배기의 "입력: [배지] (음향 콘솔 추정)"은 연결 음향 콘솔 → 오디오 분배기 (추정)과 "입력 출발 장비" 배지가 됐다.
- "조명 콘솔 → 조명"은 외부 지점 이름 때문에 "조명 콘솔 → 본당 조명"이 됐다.

**옮기다 찾은 어긋남** (고치지 않고 하나로 합친 방식만 적는다)

1. 영상 스위처 → 영상 hub — 영상 스위처 행은 "(SDI, PGM+CG, 선임 설명, 출력 단자 번호 [배지])", 영상 hub 행은 "(SDI 추정)", 온라인 송출 신호 흐름 절 1번은 연결 전체에 배지. 영상 스위처 행을 따랐다.
2. 영상 hub → 오디오 임베더 — 영상 hub 행은 "(선임 설명)", 오디오 임베더 행은 "SDI IN (SDI, PGM+CG, 선임 설명)". 오디오 임베더 행을 따랐다.
3. 오디오 임베더 CH1·CH2의 출발 — 오디오 임베더 행은 출발 장비 미확인, 음향 콘솔 행은 "음향 콘솔 → 오디오 임베더 (XLR, 선임 설명. 오디오 분배기 경유 여부 [배지])". 티켓대로 출발을 "음향 소리"(미상)로 두고 후보에 음향 콘솔·오디오 분배기, 근거에 "선임 설명(음향 콘솔)"을 적었다.
4. 백업 녹화기 → 송출 PC 캡처카드 — 백업 녹화기 행은 배지 없이 "(SDI, 선임 설명)", 송출 PC·송출 PC 캡처카드 행은 연결 전체에 배지, 신호는 "SDI 1개"와 "SDI"로 다르다. 미확인으로, 신호는 "SDI 1개"로 합쳤다.
5. 직렬 구조의 나머지 두 연결(오디오 임베더 → 백업 송출 장비, 백업 송출 장비 → 백업 녹화기)은 표에 배지가 없지만 신호 흐름 절은 직렬 구조 전체를 미확인으로 둔다. 표를 따라 미확인으로 두지 않았다.
6. "송출 PC → 공유기 → 유튜브"는 송출 PC → 공유기(미확인)와 공유기 → 유튜브 두 연결로 나눴다. 공유기 → 유튜브의 "송출 PC의 주 송출"은 새로 쓴 말이다. 공유기 행의 "인터넷 → 공유기 WAN"은 표대로 인터넷에서 들어오는 방향이라, 02가 흐름 방향을 정할 때 다시 본다.
7. 표에 없던 연결 둘을 더했다: 송출 PC 캡처카드 → 송출 PC, CG PC → CG PC 문자발생기 보드 (PCIe, 내부). 위치 칸("송출 PC 내부", "CG PC 내부")에서 나온 것이고, 02의 직렬 구조 하류 계산(… → 송출 PC 캡처카드 → 송출 PC)에 필요하다.
8. 고쳐 쓴 확인할 거리 글: 백업 녹화기 비고의 배지만 있던 자리 → "기존 기록과 용어집 정의 중 어느 쪽이 실제 녹화 방식인지", 영상 전원 시퀀서 "외 (채널별 할당)" → "채널별 할당, 그 외 연결 장비", 음향 UPS "음향 콘솔 외" → "음향 콘솔 외 공급 장비", PTZ 컨트롤러 "(IP 제어 [배지])" → 신호 "제어" + "IP 제어인지", 공유기 "LAN → 네트워크 스위치 외 장비" → "공유기 LAN에는 그 외 장비도 연결".
