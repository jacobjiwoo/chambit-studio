# 본문 범위 입력 문법과 오입력 처리

Type: grilling
Status: resolved
Blocked by: 02

## Question

사람이 본문 범위를 **어떻게 치고**, 잘못 쳤을 때 **무슨 일이 일어나는가.**

차팅에서 확정된 것 — **입력은 사람이 반드시 친다.** 목사님이 매번 따로 알려주므로 일독표·연속강해 같은 규칙이 없고, 날짜만 보고 그날 본문을 아는 길은 존재하지 않는다. 그래서 이 입력 한 칸이 도구의 **유일한 사람 접점**이고, 여기가 막히면 도구 전체가 막힌다.

### 갈라야 할 것 — 문법

- **책 이름을 어떻게 받나.** `시편` / `시` / `Psalms` / 드롭다운 선택. 목사님이 알려주는 형태를 그대로 칠 수 있어야 하는가
- **범위 표기.** `시편 23:1-6` / `시 23:1~6` / `시편 23편 1-6절`. 실제로 쓰는 표기가 무엇인지부터 확인할 것
- **장을 넘나드는 범위** (`요한복음 3:16-4:2`)를 받아야 하는가. 새벽기도가 실제로 그렇게 도는지
- **장 전체** (`시편 23편`)를 어떻게 표현하나
- **여러 구간**을 한 벌에 넣는 일이 있는가
- **자유 입력 한 칸이냐, 나눠진 칸들이냐, 선택이냐.** 자유 입력은 빠르지만 틀릴 수 있고, 선택은 틀릴 수 없지만 느리다. **매일 새벽에 도는 도구**라는 점이 저울에 올라간다

### 갈라야 할 것 — 틀렸을 때

- 없는 책·없는 장·없는 절을 쳤을 때. **개역개정은 책마다 장 수가 다르고 장마다 절 수가 다르다** — `시편 23:1-20`은 문법은 맞지만 존재하지 않는다
- 오타를 **고쳐주나, 물어보나, 막나.** 새벽 5시에 혼자 쓰는 도구라는 점을 고려할 것
- **조용히 틀리는 경우가 가장 위험하다** — 범위를 잘못 해석해 다른 본문이 나왔는데 사람이 눈치채지 못하면 회중 앞 화면에 틀린 성경이 뜬다. 이걸 구조적으로 막는 장치가 필요한지
- 이 티켓이 화면 전체의 실패 상태까지 다루지는 않는다. 맵의 `Not yet specified`에 *"틀린 입력·없는 구절이 새벽 5시에 나왔을 때"* 가 더 넓은 안개로 남아 있다

### 데이터가 가진 것 (02, resolved)

키는 **평면 문자열** `"창1:1"` — **책 약어 + 장 + `:` + 절**. 중첩 구조가 아니라 **파싱해야 하는 문자열**이고, 66권·1,189장·**31,088항목**이 빠짐없이 들어 있다(없어진 절 0, 중복 0).

이 티켓이 알아야 할 것 둘:

- **약어가 이미 데이터의 키다.** 사람이 `시편`이라 쳐도 데이터는 `시`로 갖고 있다. 정식 이름 ↔ 약어 매핑을 **우리가 들고 있어야 한다** — 데이터에 약어 표가 따로 들어 있지 않다
- **`행24:7`은 존재하지 않는다.** 개역개정이 이 절 번호를 아예 안 찍기 때문이고(24:6 끝에 `(6하반-8상반 없음)`만 적는다), 데이터도 정본을 따라 없다. **"문법은 맞는데 존재하지 않는 절"의 실제 사례**이므로 오입력 처리 설계의 시험대로 쓸 것. 같은 성격으로 `(없음)`만 든 항목이 13개 더 있다
- **깨진 키 `요18:이`가 하나 있다** — 소제목이 요 18:38 본문을 끊으면서 첫 글자가 절 번호로 먹혔다. **지금 요 18:38은 반쪽만 나온다.** 데이터 정제는 `성경 데이터가 어디에 사는가`가 맡지만, 파싱이 이런 키를 만났을 때 어떻게 구는지는 이 티켓의 몫이다

## Answer

**문법을 설계하지 않는다. 입력은 선택이다.**

티켓은 *"사람이 어떻게 치나"* 로 적혀 있었지만, 그리기 전에 **치는 게 맞는지**가 뒤집혔다. 앱이 성경 데이터를 품고 있으므로(차팅 확정 사항) 사람은 **가진 데이터에서 고르면 된다.** 자유 텍스트 파싱은 없다.

이 결정 하나가 티켓의 절반을 죽인다:

- **약어 매핑 문제가 사라진다.** `요한일서` / `요일` / `요1서`를 알아들을 필요가 없다. 화면엔 정식 이름을 띄우고 내부적으로 데이터 키(`요일`)를 쓴다. 조사 02가 *"티켓 06이 알아야 할 함정"* 이라 표시한 **접두사 겹침 7쌍**(`요`⊂`요일`/`요이`/`요삼`, `삼상`/`삼하`, `고전`/`고후`, `살전`/`살후`, `딤전`/`딤후`, `대상`/`대하`, `왕상`/`왕하`)은 파싱을 안 하니 **발동하지 않는다.**
- **"없는 책·없는 장·없는 절"이 구조적으로 불가능해진다.** 티켓이 시험대로 지목한 `시편 23:1-20`은 목록에 23편이 6절까지만 있으면 **고를 수가 없다.** `행24:7`(개역개정이 아예 안 찍는 절)도, `(없음)`만 든 13개 항목도 마찬가지다 — 데이터가 목록의 출처이므로 없는 것은 뜨지 않는다.

즉 티켓의 "틀렸을 때" 절반은 **처리할 문제가 아니라 만들 수 없는 상태**가 됐다. 자막 추출기가 *"편집 없음"* 으로 얻어낸 것과 같은 종류의 이득이다.

### 1. 고르는 수단 — 지를 수 있는 목록

칸에 몇 글자 치면 후보가 좁혀지고, **확정은 반드시 목록에서** 한다. 자유 입력의 속도와 선택의 안전을 둘 다 갖는다.

순수 드롭다운은 기각했다 — **시편은 150장이고 119편은 176절**이다. 매일 새벽 5시에 처음 보는 당번이 그걸 스크롤하는 설계는 성립하지 않는다(맵의 *"설명 없이 돌아가야 한다"*). 격자 드릴다운도 기각 — 붙어 있는 칸 사이 오클릭이 스크롤보다 쉽다.

**부수 이득 하나** — `요`만 쳤을 때 `요한복음`·`요한1서`·`요한2서`·`요한3서`·`요엘`이 **나란히 보인다.** 조사가 함정이라 부른 접두사 겹침이, 파싱에서는 위험이었는데 목록에서는 **오해당이 눈에 드러나는 장치**가 된다.

(픽셀 배치는 `화면 구성과 조작 흐름`의 몫이다. 여기서 정한 것은 수단의 성격이고, 08은 이것을 전제로 받는다.)

### 2. 범위 — 끝은 시작부터 이어지는 한 목록

**장을 넘나든다.** 시작(책·장·절)을 고르면 **끝 후보가 그 절부터 이어서 흘러간다** — `3:17` … `3:36`, `4:1`, `4:2` … 칸을 늘리지 않고 장 넘김이 공짜가 된다.

```
시작  [요한복음 ▾] [3장 ▾] [16절 ▾]
끝    [4장 2절 ▾]   ← 목록이 16절부터 이어짐
```

파생 셋:

- **역순 범위가 불가능하다.** 시작보다 앞을 고를 방법이 없다
- **끝 목록은 책 끝에서 멈춘다.** 요한복음 21:25 다음에 사도행전이 이어지지 않는다 — 책을 넘나드는 새벽기도 본문은 없다
- **장 전체는 따로 표현하지 않는다.** 시작 1절 + 끝 마지막 절이면 장 전체다

**끝 지점의 기본값은 시작과 같은 절**로 둔다. 장 마지막을 기본으로 두면 사람이 안 건드렸을 때 **조용히 큰 범위**가 만들어지고, 같은 절이면 최소 범위라 실수해도 티가 난다. (배치와 함께 08에서 실물로 확인할 수 있다.)

### 3. 하루 치는 범위 하나가 아니라 **범위의 목록**이다

담당자 확인 — **떨어진 구간이 둘 이상 들어가는 날이 있고, 세 형태가 전부 나온다**: 아예 다른 책(`시편 23편` + `요한복음 3:16-18`), 같은 책의 다른 장(`요한복음 3장` + `14장`), 같은 장 안에서 건너뛰기(`마태복음 5:1-3` + `5:10-12`).

셋 다 나오므로 **특수 케이스를 만들지 않는다** — 구간마다 책·장·절을 통째로 다시 고르는 **한 가지 모양**이 세 경우를 전부 덮는다. 구간 추가는 §1·§2의 입력 한 벌을 복제하는 것이다.

(직전 구간의 책·장을 미리 채워두면 뒤의 두 형태는 타이핑이 거의 없다. 편의이지 모델이 아니므로 08의 몫.)

**순서는 고른 순서 그대로다.** 성경 순서로 자동 정렬하지 않는다 — 목사님이 읽는 순서가 성경 순서라는 보장이 없고(요한복음 → 시편일 수 있다), 우리가 재정렬하면 그건 **조용히 순서를 바꾸는 것**이며 아무도 경고를 못 본다. 자막 추출기가 *"쪼개지도 dedupe하지도 않고 등장 순서 그대로"* 로 닫은 자리와 같다.

**겹치는 구간을 막지 않는다.** `마 5:1-3` + `5:2-5`를 골랐으면 그대로 나간다. 같은 자막이 두 번 나가므로 중복 제거를 금지했던 자막 추출기와 같은 원리이고, 어차피 §4의 미리보기에 전부 보인다.

### 4. 조용히 틀리는 경우 — 검증이 아니라 노출로 막는다

선택으로 바꿔도 이건 안 죽는다. 모양만 바뀐다:

- 좁혀진 목록에서 **한 칸 아래 `요한1서`**를 확정한다 → 둘 다 3장 16절이 존재한다
- `3`을 칠 때 손이 미끄러져 `33` → 시편이면 존재한다
- 끝을 `4:2` 대신 `4:12` → 존재한다

셋 다 **문법적으로 완벽하고 검증을 전부 통과한다.** 막을 수 있는 장치는 검증이 아니라 **보여주기** 하나뿐이다.

**고른 즉시 절 번호와 함께 본문 전문이 뜬다.** 위에 참조와 **총 절 수**가 붙는다. 어차피 그 글자들이 슬라이드에 들어가므로 미리보기가 공짜다.

```
요한복음 3:16 – 4:2  ·  23절
───────────────────────────
16  하나님이 세상을 이처럼 사랑하사…
17  하나님이 그 아들을 세상에…
 ⋮
 2  예수께서 친히 베푸시지 아니하시고…

            [ .pptx 받기 ]  ← 항상 활성
```

**게이트는 두지 않는다.** "본문을 확인했습니다" 체크나 확인 모달은 **매일 도는 도구에서 3일이면 무의식적 클릭**이 된다 — 안전은 안 늘고 비용만 매일 물린다. 자막 추출기가 *"막았을 때의 위험은 편집 대신 노출로 갚는다"* 로 정리한 자리와 같고, 거기서도 강제 확인 단계는 없었다.

### 5. 목록을 만드는 규칙 — 데이터 키를 그대로 믿지 않는다

목록의 출처는 **데이터 자체**다. 책마다 장 수, 장마다 절 수를 `bible.json` 키에서 만든다.

**단 절 번호가 숫자인 키만 목록에 올린다.** 안 그러면 요한복음 18장의 절 목록에 깨진 키 `요18:이`의 `이`가 **절 번호 자리에 끼어든다.**

**다만 이걸 막아도 요 18:38이 반쪽으로 나오는 것은 안 고쳐진다.** 후반부가 `요18:이` 안에 갇혀 있고, 이 앱에서 그 절을 고르면 **화면과 슬라이드에 반쪽만 뜬다** — §4의 미리보기도 이건 못 잡는다(요 18:38을 외우고 있는 사람이 없다). **데이터 안에 이미 존재하는 "조용히 틀리는" 실제 사례 하나**이며, 정제는 `성경 데이터가 어디에 사는가`(05)의 몫이므로 그리로 넘긴다.

**약어 매핑표 66개는 앱이 들고 있다.** 데이터에 표가 없기 때문이고, 조사 02가 공회 표기와 대조해 실측해 뒀으므로(불일치 0) 새로 조사할 것은 없다.

> ### ⚠ 정정 — §5의 규칙이 지금은 틀렸다 (`성경 데이터가 어디에 사는가`, 2026-08-10)
>
> **위의 *"절 번호가 숫자인 키만 목록에 올린다"* 를 그대로 쓰면 정본에 멀쩡히 있는 병합절 11개가 목록에서 사라진다.**
>
> ```
> 신6:18-19  신15:4-5  신30:9-10  대상16:12-13  시92:1-3  시105:5-6
> 렘32:3-5  렘33:10-11  겔24:4-5  행15:25-26  롬9:1-2
> ```
>
> 이 규칙은 깨진 키 `요18:이`를 막으려고 세운 것인데 **막을 대상이 데이터 교체로 이미 사라졌고**(위 "넘긴 것" 참조), 규칙만 남아 애먼 것을 떨어뜨린다. 이 티켓이 *"안전망으로 유지할 것"* 이라 적었던 판단이 뒤집힌 자리다 — **안전망이 아니라 그물코가 너무 촘촘했다.**
>
> 대신 **05가 배포 데이터에 병합절 예외표를 명시적으로 싣기로 했다.** 목록은 절 번호를 키 파싱으로 추측하지 말고 그 표를 볼 것. 목록에는 `18-19`처럼 **정본 그대로 뜨는 것이 맞다** — 종이에도 그렇게 찍혀 있고, 담당자가 목사님에게 받은 범위와 대조하는 것도 종이다.
>
> 파생 하나 — **§5의 *"약어 매핑표 66개는 앱이 들고 있다"* 도 05가 이미 만들어 놨다**: [`tools/canon.json`](../tools/canon.json)에 66권의 약칭·**정식 이름**(`창세기`)·공회 코드·장 수가 들어 있다(합 1,189장 assert). 새로 만들지 말 것.

### 이 티켓이 답할 수 없어 떼어낸 것

**구간이 둘 이상일 때 슬라이드가 그 경계를 표시하는가** — 맵의 전제는 `[인트로] → [절] → … → [아웃트로]` 한 줄기인데, 구간이 둘이면 그게 맞는지 모른다. 구분 슬라이드가 들어가는가, 절 슬라이드에 참조가 뜨는가. **실물을 봐야 안다** → [`12-multi-range-slide-boundary`](12-multi-range-slide-boundary.md) (01이 막음). `새벽기도 PPT 실물 확보와 조판 실측`의 확인 항목에도 *"구간이 둘이었던 날의 실물"* 을 추가했다.
