# 앉을 자리 — 라우팅·모듈 경계·홈 목록

Type: grilling
Status: open
Blocked by: 04, 05, 08

## Question

이 도구가 저장소 **어디에 앉고**, 홈 목록이 **어떻게 바뀌는가.**

앞선 작업이 규약을 이미 세워 뒀으므로 대부분은 확인이고, **한 가지만 진짜 결정**이다.

### 이미 정해진 것 (확인만 한다)

- **"폴더 하나 = 경로 하나"** — `app/subtitle-extractor/`. 이 도구도 `app/<slug>/`에 앉는다. 경로 이름을 정할 것
- `_lib/` · `_components/` 자름, Vitest, 공용 디렉터리 안 만들기 — 자막 추출기의 `확장을 감당할 최소 뼈대`가 정한 그대로

### 진짜 결정 — 홈 목록의 분류 헤딩

`app/page.tsx` 주석이 조건을 명시적으로 예약해 뒀다:

> **`도구`/`문서` 분류 헤딩은 안 만든다.** 각 묶음에 항목이 하나씩이라 정보가 0이다. **셋째가 올 때 가른다.**

**이 도구가 셋째다.** 조건이 발동했다. 다만 예약 당시의 가정을 다시 볼 것 — 셋째가 오면 `도구` 2 · `문서` 1이 되는데, **그때 헤딩이 정보를 갖는가.** 예약은 "셋째가 오면 가른다"였지 "셋째가 오면 반드시 갈라야 한다"가 아니다. 조건이 발동했다고 결론이 자동으로 따라오지는 않는다.

### 남은 것

- **번들에 무엇이 들어가는가** — `생성 방식`이 템플릿 파일을, `성경 데이터가 어디에 사는가`가 성경 데이터를 정한다. 정적 자산이 어디에 앉는지(`public/` vs route handler vs import)를 여기서 정리한다
- **`.gitignore`** — 차팅에서 확인된 구멍 둘: `*.pptx`·`*.potx` 규칙이 없고 `*.json` 규칙도 없다. 앞선 작업이 원고와 PDF에 대해 세운 방어와 같은 층에 놓을 것인지
- 모듈 경계를 **함수 하나로 긋는 자리**가 있는가 — 자막 추출기는 `parseHwp(bytes) => StyledRun[]` 하나로 포맷 경계를 그었고 추상화를 만들지 않았다. 여기 대응하는 자리는 아마 "범위 → 절 배열"과 "절 배열 → pptx 바이트" 둘이다

### 입력

`생성 방식 — 템플릿이냐 백지냐` · `성경 데이터가 어디에 사는가` · `화면 구성과 조작 흐름`.
