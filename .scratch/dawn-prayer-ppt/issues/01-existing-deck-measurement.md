# 새벽기도 PPT 실물 확보와 조판 실측

Type: task
Status: open

## Question

물려받아 매일 복제해 쓰고 있는 **새벽기도 PPT 실물을 확보**하고, 그 안의 조판을 **숫자로** 꺼낸다.

이 티켓이 없으면 조판 결정 전부가 추측 위에 선다. 자막 추출기 맵의 `설교 원고 실물 확보`가 정확히 이 자리였고, 거기서 *"빨간색은 `#FF0000` 하나"* 라는 확정이 나와 뒤따르는 규칙 티켓 전체가 실측 위에 앉았다.

차팅 세션에서 확인된 것 — **이 파일은 작업 컴퓨터에 없다.** 확보 자체가 이 티켓의 첫 절반이다.

### 확인할 것 — 파일 정체

- 확장자가 `.pptx`인가 `.ppt`인가 (구형 `.ppt`면 OOXML이 아니라 OLE 복합 파일이고, 템플릿으로 재사용하는 길의 난이도가 완전히 달라진다)
- 파일 크기, 그중 배경 이미지가 차지하는 비율
- 슬라이드 크기 — 4:3(10×7.5in)인가 16:9(13.333×7.5in)인가
- **슬라이드 마스터·레이아웃이 실제로 쓰이고 있는가**, 아니면 슬라이드마다 상자를 직접 얹었는가. 템플릿 갈아끼우기의 성패가 여기 걸린다

### 확인할 것 — 절 슬라이드의 조판

- 폰트 이름과 **정확한 크기(pt)**. 한글 폰트와 영문 폰트가 갈려 있는지도
- 텍스트 상자의 **위치와 크기(EMU 또는 inch)**
- 줄간격, 자간, 정렬(가운데/왼쪽), 세로 정렬
- 글자색, 그림자·윤곽선 같은 효과
- **자동 맞춤(autofit) 설정** — `제목에 맞춰 도형 크기 조정` / `넘치면 텍스트 크기 축소` / `안 함` 중 무엇인가. 이게 켜져 있으면 "넘침"의 정의 자체가 달라진다
- **절 번호가 화면에 있는가.** 있다면 어떤 모양인가 — 본문 앞에 붙는가, 따로 떨어져 있는가, 서식이 다른가

### 확인할 것 — 앞뒤와 운영

- 인트로·아웃트로 슬라이드의 실제 내용. 정말 배경 이미지뿐인가, 숨은 텍스트 상자가 있는가
- 배경 이미지의 포맷·해상도·파일 크기
- 실제 파일에서 **한 슬라이드에 절이 몇 개** 들어가 있는가. 차팅에서는 "절 단위"라고 했지만 실물이 다를 수 있다
- **구간이 둘 이상이었던 날의 실물을 찾는다.** `본문 범위 입력 문법과 오입력 처리`가 확인한 바 하루 치에 **떨어진 구간이 둘 이상 들어가는 날이 있다**(다른 책 / 같은 책 다른 장 / 같은 장 안 건너뛰기 세 형태 전부). 그런 날 슬라이드가 **경계를 어떻게 표시했는지** — 구분 슬라이드가 있었는가, 절 슬라이드에 참조가 떴는가, 인트로가 가운데에도 있었는가. **이게 맵의 `[인트로] → [절] → … → [아웃트로]` 한 줄기 전제를 검증한다.** [`12-multi-range-slide-boundary`](12-multi-range-slide-boundary.md)의 직접 입력이며, 사례가 아예 없으면 "없었다"도 답이다
- 파일 이름 규칙 (`Not yet specified`의 한 항목이 여기서 걷힌다)
- 가능하면 **최근 것 여러 벌**을 본다 — 한 벌만 보면 그날의 예외를 규칙으로 오해한다. 본문 길이가 짧은 날과 긴 날이 섞이면 더 좋다

### 확인할 것 — 예배당 PC (`생성물이 파워포인트에서 실제로 열리는가`가 남긴 것)

**같은 걸음에 끝낸다.** 10이 macOS에서 *"열린다"* 를 확인하고 **Windows 확인만 남겨 뒀는데**, 그건 예배당에 가야만 되는 일이라 이 티켓과 같은 트립이다. 따로 잡으면 교회를 두 번 간다.

- **10이 만든 `.pptx` 셋(`min` / `swapped` / `af-bare`)을 USB에 담아 가서 예배당 PC에서 연다.** macOS와 같은 결과인가
- **맑은 고딕이 그 PC에 실제로 깔려 있는가.** 조사 03이 *"폰트 임베딩은 불필요하다"* 고 판단한 근거가 이 가정이었다. 없으면 임베딩 판단이 다시 열린다
- **파워포인트 줄높이 상수 실측.** 10이 줄바꿈 21자는 맞혔지만 줄높이는 아직 종이 위의 값이다. `절이 넘칠 때 어떻게 쪼개나`가 넘침을 계산하려면 이 상수가 있어야 한다
- 파워포인트 버전, 그리고 **인터넷이 되는가** (되든 안 되든 도구는 전날 밤에 도니까 판단 근거는 아니다. 다만 안 되면 "그 자리에서 급히 고친다"는 길이 아예 없다는 뜻이라 알아 둘 값은 있다)

> **주의 — 이제 예배당 PC는 도구를 돌리는 자리가 아니라 파일을 여는 자리다.** `성경 데이터가 어디에 사는가`가 확인한 대로 **생성은 전날 밤 집에서** 일어난다. 여기서 잴 것은 *"이 PC에서 도구가 도는가"* 가 아니라 **"전날 밤에 만들어 간 파일이 여기서 똑같이 보이는가"** 다.

### 결과 기록

- 실물 파일을 어디에 둘지 먼저 정한다. **`.gitignore`에 `*.pptx`·`*.potx` 규칙이 없다** — 배경 이미지가 교회 자산이므로 커밋 여부를 판단하고, 커밋하지 않기로 하면 규칙을 먼저 추가한 뒤 파일을 들인다(자막 추출기 맵이 *"`git init` 전에 `app/prototype/`을 먼저 삭제하는 순서 자체를 안전장치로 쓴다"* 고 한 것과 같은 수법)
- 위 항목의 답을 수치로 적는다. "크다/작다"가 아니라 pt와 EMU로
- 텍스트 상자의 폭·높이와 폰트 크기는 **`절이 넘칠 때 어떻게 쪼개나`의 직접 입력**이다. 그 티켓이 계산할 수 있는 형태로 남긴다
