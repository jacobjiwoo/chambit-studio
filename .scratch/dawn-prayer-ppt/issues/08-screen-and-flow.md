# 화면 구성과 조작 흐름

Type: prototype
Status: open
Blocked by: 06, 07

## Question

사람이 이 도구 앞에 섰을 때 **무엇을 보고 무엇을 하는가.**

자막 추출기의 `화면 구성과 조작 흐름`에 대응하는 자리다. 거기서는 **읽기 전용 2단**으로 닫혔고, 갈래 여섯을 실제로 만들어 나란히 놓고 골랐다. 같은 수법을 쓰되 **전제가 다르다는 점**을 먼저 잡을 것.

### 자막 추출기와 다른 전제 셋

1. **입력이 파일이 아니라 글자다.** 드롭존이 없다. 칸 하나에 `시편 23:1-6`을 친다
2. **산출물을 사람이 고친다.** 자막 추출기는 *"고칠 일은 원고를 고쳐 다시 올린다"* 로 편집을 통째로 막았다. 여기선 파워포인트에서 고치는 것이 이미 확정돼 있다. **그러면 미리보기의 역할이 달라진다** — 자막 추출기의 미리보기는 "받기 전 확인"이었는데, 여기선 "무엇을 고칠지 미리 아는" 용도일 수 있다
3. **매일 돌고, 여럿이 돌아가며 쓴다.** 설명 없이 돌아가야 하고, 새벽 5시에 처음 여는 사람이 막히면 안 된다

### 갈라야 할 것

- **한 화면인가, 단계인가.** 입력 → 결과가 같은 자리에서 바뀌는가(자막 추출기 방식) 아니면 넘어가는가
- **미리보기가 있는가, 무엇을 보여주는가.** 슬라이드를 그려 보여주는가, 절 목록만 보여주는가, 아무것도 안 보여주고 바로 파일을 주는가. **넘치는 절 경고를 여기서 띄운다면** 미리보기는 필수가 된다
- **입력 확인을 어떻게 하나.** 친 범위가 맞게 해석됐는지를 사람이 눈으로 확인하는 자리가 필요한가 — `06`이 *"조용히 틀리는 경우가 가장 위험하다"* 고 남긴 문제를 화면이 받을 수 있다
- **날짜·파일 이름을 사람이 정하나, 도구가 정하나**
- **결과가 어떻게 손에 들어오나.** 다운로드 하나뿐인가, 다시 만들기가 쉬운가

### 방법

시안을 실제로 만들어 나란히 놓는다. `.scratch/dawn-prayer-ppt/prototypes/`에 둔다. 나비CG 문서 맵의 선례처럼 **돌아가는 시안이 결정보다 먼저 사실을 뒤집는 일**이 흔하다 — 거기선 검색 시안이 재현율 게이트를 미리 터뜨렸다.

### 입력

- `본문 범위 입력 문법과 오입력 처리` — 입력 칸의 모양과 실패 상태
- `절이 넘칠 때 어떻게 쪼개나` — 화면이 경고를 띄워야 하는지, 띄운다면 몇 건 규모인지
