# 화면 구성과 조작 흐름

Type: prototype
Status: open
Blocked by: 06, 07

## Question

사람이 이 도구 앞에 섰을 때 **무엇을 보고 무엇을 하는가.**

자막 추출기의 `화면 구성과 조작 흐름`에 대응하는 자리다. 거기서는 **읽기 전용 2단**으로 닫혔고, 갈래 여섯을 실제로 만들어 나란히 놓고 골랐다. 같은 수법을 쓰되 **전제가 다르다는 점**을 먼저 잡을 것.

### 자막 추출기와 다른 전제 셋

1. **입력이 파일이 아니라 ~~글자다~~ 선택이다.** 드롭존이 없다. ~~칸 하나에 `시편 23:1-6`을 친다~~ — **06이 뒤집었다**: 자유 텍스트를 파싱하지 않고 **지를 수 있는 목록**에서 책·장·절을 고른다
2. **산출물을 사람이 고친다.** 자막 추출기는 *"고칠 일은 원고를 고쳐 다시 올린다"* 로 편집을 통째로 막았다. 여기선 파워포인트에서 고치는 것이 이미 확정돼 있다. **그러면 미리보기의 역할이 달라진다** — 자막 추출기의 미리보기는 "받기 전 확인"이었는데, 여기선 "무엇을 고칠지 미리 아는" 용도일 수 있다
3. **매일 돌고, 여럿이 돌아가며 쓴다.** 설명 없이 돌아가야 하고, 새벽 5시에 처음 여는 사람이 막히면 안 된다

### 06이 이미 정한 것 — 다시 열지 않는다

- **자유 입력이냐 선택이냐**는 닫혔다. **지를 수 있는 목록**(몇 글자 치면 좁혀지고, 확정은 반드시 목록에서). 순수 드롭다운은 시편 150장·119편 176절 때문에 기각됐다
- **범위의 모양**도 닫혔다. 시작(책·장·절) + **시작부터 이어져 흐르는 끝 목록**. 역순 불가, 끝은 책 끝에서 멈춤, 장 전체는 따로 표현하지 않음. 끝 지점 **기본값은 시작과 같은 절**
- **하루 치는 범위의 목록이다.** 구간마다 입력 한 벌을 통째로 복제하고, **고른 순서 그대로** 나간다
- **미리보기가 있고 게이트는 없다.** 고른 즉시 절 번호와 함께 **본문 전문 + 참조 + 총 절 수**가 뜨고, 받기 버튼은 항상 활성. 확인 체크·확인 모달은 *"매일 도는 도구에서 3일이면 무의식적 클릭"* 이라 기각됐다
- **"조용히 틀리는 경우"의 답이 이 미리보기다.** 화면이 이 문제를 받는 게 맞고, 06이 그 형태까지 정했다

### 갈라야 할 것

- **한 화면인가, 단계인가.** 입력 → 결과가 같은 자리에서 바뀌는가(자막 추출기 방식) 아니면 넘어가는가
- **미리보기가 절 목록을 넘어 슬라이드를 그려 보여줄 필요가 있는가.** 06이 정한 것은 *"본문이 절 번호와 함께 보인다"* 까지다. **넘치는 절 경고를 여기서 띄운다면** 슬라이드 모양의 미리보기가 필요해질 수 있다
- **구간을 어떻게 더하고 지우나.** 06이 모델(범위의 목록, 순서 보존)만 정했다. 직전 구간의 책·장을 미리 채워 타이핑을 줄이는 것도 여기서 시안으로 확인할 것
- **끝 지점 기본값**을 06의 추천(시작과 같은 절)대로 둘지 실물 시안에서 확인
- **날짜·파일 이름을 사람이 정하나, 도구가 정하나**
- **결과가 어떻게 손에 들어오나.** 다운로드 하나뿐인가, 다시 만들기가 쉬운가

### 방법

시안을 실제로 만들어 나란히 놓는다. `.scratch/dawn-prayer-ppt/prototypes/`에 둔다. **돌아가는 시안이 결정보다 먼저 사실을 뒤집는 일**이 흔하다.
