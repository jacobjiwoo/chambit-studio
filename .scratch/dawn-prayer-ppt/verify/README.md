# 실물 확인용 `.pptx` — 예배당 PC에 들고 갈 것들

`.pptx`는 **커밋되지 않는다**(`.gitignore`). 교회 자산인 배경 이미지가 public 저장소에
들어가는 것을 막기 위해 규칙을 먼저 세웠다 — 판단은 티켓 01이 실물을 보고 한다.
이 README만 커밋된다.

`생성물이 파워포인트에서 실제로 열리는가`(티켓 10)가 macOS에서 만들고 확인한 것들이다.
**Windows 확인이 남아 있고 그건 예배당 PC에서만 된다** — 티켓 01과 같은 걸음이다.

| 파일 | 무엇 | macOS에서 확인된 것 |
|---|---|---|
| `min.pptx` | `fflate`만으로 짠 최소 13파트 | 경고 없이 열리고 **텍스트 상자가 실제로 편집된다** |
| `swapped.pptx` | 템플릿 수술 — `tpl.pptx`의 가운데만 갈아끼움 | **배경·폰트가 그대로** |
| `af-bare.pptx` | `normAutofit` 없이 넘치게 둔 것 | **안 줄었다**(파워포인트도 `normAutofit`을 무시한다) |
| `tpl.pptx` | 수술 대상이 된 템플릿 | — |
| `inherited.pptx` | 물려받은 파일 자리에 세운 대역 | 실물이 아니다. 티켓 01이 진짜를 가져온다 |

## 예배당 PC에서 볼 것

1. **넷이 macOS와 같은 결과인가.** 특히 `min.pptx`가 "복구가 필요합니다" 없이 열리는가
2. **맑은 고딕이 그 PC에 깔려 있는가** — 조사 03이 *"폰트 임베딩은 불필요하다"* 고 판단한 근거가 이 가정이었다. 없으면 임베딩 판단이 다시 열린다
3. **줄바꿈이 21자에서 일어나는가** — 폰트 상수 접근(한글 음절 11,172개가 전부 같은 advance 폭)이 Windows에서도 서는지
4. **줄높이 상수 실측** — 10이 줄바꿈은 맞혔지만 줄높이는 아직 종이 위의 값이다. `절이 넘칠 때 어떻게 쪼개나`가 넘침을 계산하려면 필요하다

> **여기서 재는 것은 "이 PC에서 도구가 도는가"가 아니다.** `성경 데이터가 어디에 사는가`가
> 확인한 대로 **생성은 전날 밤 집에서** 일어난다. 예배당 PC는 파일을 여는 자리이므로,
> 질문은 **"전날 밤에 만들어 간 파일이 여기서 똑같이 보이는가"** 다.
