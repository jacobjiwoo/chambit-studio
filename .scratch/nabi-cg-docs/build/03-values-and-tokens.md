# 03 — 값 파일 단일 출처 + 토큰 치환 (게이트 2·3)

**What to build:** 글자 속성 페이지에 **참빛교회 기준값 블록이 확인일과 함께 실제 숫자로**
뜬다. 본문 마크다운에는 토큰만 들어 있고 빌드가 치환한다. 값 파일에 빈 칸이 남거나 미치환
토큰이 새면 **배포가 안 된다.**

```markdown
> **참빛교회 기준값** (2026-08-03 확인)
> 설교 자막 — Height 72 / Width 95% / Kerning −3 / Leading 110%
```

독자는 **그 자리에서 숫자를 본다.** 진입이 검색이라 *"값은 저쪽 페이지 보세요"*는 성립하지
않는다.

**Blocked by:** 01 — 방송실 PC 실측 한 번 (값 12칸이 이 티켓의 입력이다) · 02 — 뼈대
(`buildDocs()`와 렌더 경로가 서 있어야 한다).

**Status:** ready-for-agent

## 값 파일 하나가 단일 출처

구멍 둘을 나란히 놓으니 같은 값의 다른 조각이었다 — "설교 자막 한 세트"를 두 페이지가 따로
인용하면 **폰트를 바꾸는 날 동시에 낡는다.** 그래서 값 파일 하나가 단일 출처이고, 본문에는
토큰만, 치환은 빌드가 한다.

- 값마다 **출처 파일과 확인일**이 붙는다 — `출처: 2026-08-03 설교자막.카사`
- **자동 만료는 안 건다.** 아무도 안 만졌는데 어느 날 배포가 깨지는 것은 유효기간을 거부한 것과
  같은 냄새다
- **토큰 치환이 렌더 앞에 선다**

## 배지를 안 늘린다

**화면에서는 블록이 스스로 말한다.** `[추론]` 배지는 *"이 문장은 **틀렸을 수 있다**"*이고 우리
값은 *"**낡을 수 있다**"*이다. 우리 값은 오히려 매뉴얼보다 정확하므로(compix는 우리 자막이
어떤지 모른다) 한 배지에 섞으면 **가장 믿을 만한 문장에 「틀렸을 수 있음」이 붙어 배지가
거짓말을 한다.**

## 게이트가 값 파일에만 걸린다

대칭이 안 맞는 것이 의도다 — **숫자 자리가 비면 페이지가 깨지고, 문장 자리가 비면 그 문장이
없을 뿐 페이지는 매뉴얼 사실만으로 성립한다.** 하중이 다르다. 그래서 `[운영]` 문장에는
게이트를 걸지 않는다.

- [ ] 값 12칸이 `_values` **한 파일**에 있다
- [ ] 값마다 출처 파일과 확인일이 붙어 있다
- [ ] 본문 마크다운에 숫자가 직접 박혀 있지 않다 — 토큰만 있다
- [ ] 글자 속성 페이지에 기준값 블록이 확인일과 함께 숫자로 뜬다
- [ ] **게이트 2** — 값 파일에 빈 칸이 하나라도 있으면 테스트가 실패한다
- [ ] **게이트 3** — 렌더된 본문에 미치환 토큰이 하나라도 있으면 테스트가 실패한다
- [ ] 두 게이트 다 `buildDocs()` **산출물**에 대한 `expect()`다 — 치환기 내부를 보지 않는다
- [ ] 기준값 블록에 `[추론]` 배지가 안 붙는다
- [ ] `[운영]` 문장에는 게이트가 안 걸린다
- [ ] 값을 한 곳에서 고치면 그 값을 쓰는 모든 페이지가 함께 바뀐다
