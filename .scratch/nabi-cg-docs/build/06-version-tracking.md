# 06 — 버전 추적: History 파일 + 게이트 4·5·6

**What to build:** 방송실 PC의 나비CG를 업데이트한 사람이 **저장소에서 할 일이 있다는 사실을
테스트 실패 메시지로 안다.** 상수를 올리면 화면 보고 쓴 문장이 **전부 한꺼번에 터지고**, 하나씩
다시 보며 날짜를 올려야 통과한다.

**추적 대상은 compix의 최신이 아니라 우리 PC다.** 게시판을 감시해도 판단할 버전 번호가 없고
(5년째 `2.5`), 반대로 **놓칠 수 없는 사건이 하나 있다** — 방송실 PC가 한 대이고 업데이트는
사람이 직접 한다. **우리가 업데이트를 안 하면 문서도 안 낡는다 — 자기정합적이다.**

**Blocked by:** 04 — 사이드카 (게이트 5가 사이드카의 `[화면]` 태그를 읽는다).

**Status:** resolved

## 저장소가 드는 것 둘

```ts
// _meta/nabi-build.ts   (_ 접두 폴더는 Next 라우팅에서 제외된다)
export const NABI_BUILD = '2026.02'
```

```markdown
<!-- _meta/nabi-history.md -->
## 2026.02
- 페이지리스트 윈도우의 File Browser 사용 여부 선택 메뉴 추가 (창 › File Browser, Ctrl+Shift+F8)
  영향: §7
- 기타 오류수정(단축키 적용되지 않는 문제)
  영향: 없음
```

History는 compix 게시글 하단의 `- History -`에서 옮겨 적는다(2021.04~2026.02, 13차례).
**`[원본 p.NN]` 문장이 낡는 경우는 테스트가 못 본다.** 그래서 History를 저장소가 들고 항목별
영향 판정을 강제한다.

## 게이트 셋

| # | 검증 | 잡는 것 |
|---|---|---|
| 4 | `NABI_BUILD` == History 최신 항목 날짜 | 상수만 올리고 History를 안 옮겨 적는 것 |
| 5 | 모든 `[화면 YYYY.MM]` 태그 == `NABI_BUILD` | 화면 보고 쓴 문장이 새 빌드에서 재확인 없이 지나가는 것 |
| 6 | History 모든 항목에 `영향:` 줄 | 새 History 줄을 옮겨만 적고 판정을 건너뛰는 것 |

**5번이 부러 아프다.** 현재 물량 10줄 내외라 감당된다. **실패 메시지가 3단계 절차와 재확인할
줄 목록을 그대로 출력한다** — 읽을 문서를 찾아다니지 않게 하는 것이 이 메시지의 전부다.

```
① History에 항목과 `영향:` 추가
② NABI_BUILD 변경
③ 아래 N줄의 [화면] 태그를 화면에서 재확인하고 날짜를 올린다
   - <페이지> : <문장>
   …
```

**시간 기반 장치가 하나도 없다.** 세 게이트 전부 **사람이 파일을 바꾸는 순간에만** 깨진다.
달력이 넘어가도 빌드는 조용하다.

## 게이트가 못 잡는 것 — 알고 받는다

- 상수를 **안** 올리면 아무것도 안 터진다. 게을러서 갱신을 안 하는 경우는 테스트의 사각이고
  **그 구멍은 푸터의 compix 대조 유도가 받는다**(02가 세워 뒀다)
- `영향:` 판정을 **틀리게** 적으면 조용히 통과한다. 판정은 사람의 일이고 테스트는 판정의
  *존재*만 강제한다

**책임은 네 겹으로 갈라 사람 이름이 어디에도 안 들어간다** — ① 빌드 게이트 ② 실패 메시지
③ 저장소 문서 한 문단 ④ 푸터의 대조 유도. 이 티켓이 ①②③을 세운다.

- [x] History가 저장소 안에 있고 compix 게시글의 ~~13차례~~ **15차례**가 옮겨져 있다
- [x] 항목마다 `영향:` 줄이 있고 판정이 1차 7개 섹션 기준으로 적혀 있다 (31줄)
- [x] **게이트 4** — `NABI_BUILD`가 History 최신 항목 날짜와 다르면 실패한다
- [x] **게이트 5** — `NABI_BUILD`와 다른 `[화면]` 태그가 하나라도 있으면 실패한다
- [x] **게이트 6** — `영향:` 줄이 없는 History 항목이 있으면 실패한다
- [x] 게이트 5의 실패 메시지가 3단계 절차와 **재확인할 줄 목록**을 그대로 출력한다
- [x] 저장소 문서에 한 문단이 있다 — *"방송실 PC의 나비CG를 업데이트했다면 저장소에서 할 일이 있다"*
- [x] 시간 기반 장치가 하나도 없다 — 달력이 넘어가도 빌드가 조용하다

- [x] 세 게이트 다 `buildDocs()` 산출물과 `_meta` 파일에 대한 `expect()`다

## 닫으며 확인한 것 셋

구현 커밋(`3e93658`)이 티켓의 Status와 체크박스를 안 건드리고 지나가, 12를 끝낸 뒤 열 칸을
실물로 하나씩 다시 봤다. 셋만 적어 둔다.

**① History는 13차례가 아니라 15차례다.** 티켓이 든 13은 맵의 추정이고 게시글을 실제로 옮겨
적으니 15회차(2021.04~2026.02) · 항목 31개였다. **판정 물량이 티켓 예상보다 컸다는 뜻이고**,
그래도 `영향: 없음`이 다수라 게이트 6이 강제한 비용은 예상 안에 있었다.

**② 게이트 5는 오늘 공회전한다.** 저장소의 `[화면]` 태그가 **지금 0줄**이다 — 1차 다섯 장 중
본문이 있는 둘(글자 속성 · 도형 속성)이 `[원본]`·`[추론]`·`[운영]`만 쓴다. 태그가 실제로
붙는 곳은 10(단축키 누락 3개)과 11(`§6.1` 토글 · `§6.2` 모드)이고, **둘 다 01의 실측을 입력으로
받는다.** 즉 이 게이트는 01이 다녀와야 처음으로 무는 것이고, 티켓이 예상한 "10줄 내외"도
그때 재는 숫자다. 뒤집힐 조건 40줄까지는 여유가 크다.

**③ 시간 기반 장치 0건을 grep으로 확인했다** — `app/docs/nabi-cg/` 전체에 `new Date`·`Date.now`·
`getFullYear`가 하나도 없다. 세 게이트 다 사람이 `NABI_BUILD`나 `nabi-history.md`를 바꾸는
순간에만 깨진다.
