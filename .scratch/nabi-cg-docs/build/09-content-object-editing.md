# 09 — 본문: 객체 편집

**What to build:** `객체 편집` 페이지가 열린다 — 자막이 길어져 크기를 조절하는 **매주 하는
작업**의 본거지다. 원본 `Ch2 §3.2` 6페이지.

`Ctrl+B` 일괄 지정이 여기 있다. **매주 그 작업을 하는 본인이 *"아마 쓸걸...? 확실하진 않아"*라고
말한 자리**이고, 이 문서가 존재하는 이유 중 *"모르는 것을 영영 모른다"*의 대표 사례다.

**Blocked by:** 04 — 사이드카 + 배지 (**충족됨**).

~~01 — 방송실 PC 실측~~ · ~~03 — 값 파일 + 토큰 치환~~ → **07과 같은 방식으로 미룬다**
(근거 전문은 01 §쪼갠 이유). 화면 한글 이름 대조와 값 블록은 열린 칸으로 남는다.

**Status:** ready-for-human — **본문 한 장은 열렸다.** 열한 항목 중 열이 닫혔고 남은 하나가
`01a`(화면 한글 이름 대조)의 몫이다. 07·08과 같은 모양으로 끝난다.

## 이 페이지가 특별히 조심할 것

원본 `§3 편집`은 52페이지인데 **여기서 6페이지만 가져온다.** 작업에 안 걸리는 나머지는 안
들어온다 — 다만 `H2 나머지 속성` 레퍼런스 표가 *"이런 것도 있었네"*를 받는다.

**여러 방법이 있을 때 손대는 순서를 적는다.** 위에서부터 시도하고 안 되면 다음으로 내려가는
형태여야 한다. 순서에 대한 판단 문장(*"Kerning을 먼저 쓰는 편이 낫다"*)은 값 파일에 못 들어가고
본문에 그대로 쓰되 사이드카 `[운영]`으로 등록한다.

- [x] 기본형 슬롯 다섯이 다 있다
- [x] 페이지 안쪽 H2가 **작업**으로 갈려 있다 — *"자막이 한 줄에 안 들어갈 때"* 같은 제목이다
- [x] 여러 방법이 있는 작업에 **손대는 순서**가 번호로 붙어 있다
- [x] `Ctrl+B` 일괄 지정이 본문에 있고 무엇을 줄여 주는지가 한 줄로 적혀 있다
- [x] 판단이 섞인 문장이 사이드카 `[운영]`으로 등록돼 있다
- [x] 문장마다 태그가 붙어 있고 `[추론]` 문장에 배지가 뜬다
- [ ] **첫 등장 병기는 들어갔지만 화면 대조는 `01a`로 미룬다** — `Safe Area(안내선)`는 매뉴얼이
  이미 병기했고 `Undo/Redo(작업취소·다시실행)`는 매뉴얼의 메뉴명이다. **이 페이지는 우리가 지은
  이름이 0개다**(§지은 이름이 없다). 그래도 화면의 한글이 다르면 갈아야 하므로 07·08과 같은
  자리에 열린 칸으로 둔다
- [x] 아이콘을 경로로 가리킨다. 경로도 이름도 없는 자리는 2차로 내린다
- [x] `H2 관련`에서 글자 속성 · 도형 속성으로 가는 링크가 있다
- [x] 그림이 0장이다
- [x] 05의 재현율 게이트가 통과한다 — `일괄 지정` 질의의 유예가 풀렸고 이 페이지가 1·2위다

## 세 형제를 다 세웠다 — `Ctrl+B` 혼자가 아니었다

티켓은 `Ctrl+B` 하나를 말했는데 원본 `§3.2.12`는 **셋을 나란히 놓는다.** 셋 다 「여러 페이지를
한 번에」이고 갈리는 것은 **한 번에 바뀌는 범위**다. 하나만 적으면 나머지 둘은 매뉴얼로만
만나게 되므로 *"모르는 것을 영영 모른다"*가 그대로 남는다.

| 순서 | 메뉴 | 단축키 | 왜 이 자리인가 |
|---|---|---|---|
| 1 | 객체속성일괄지정 | `Ctrl+B` | 바꾸려는 값만 바꾼다 — 가장 좁다 |
| 2 | 같은 순서의 레이어 객체들에만 현재 속성 적용 | `Ctrl+Shift+B` | 페이지마다 같은 줄만 — 대상이 좁게 겨눠져 있다 |
| 3 | 모든 객체를 현재 속성으로 변경 | `Ctrl+Alt+B` | **위치까지 따라간다.** 잡아 둔 자리가 밀리므로 마지막이다 |

**1과 3의 갈림은 우리 판단이 아니라 원본이 적어 준 것이다**(p.29 — *"일부만 변경하고 싶다면 …
완전히 일치시키려면 …"*). 3을 마지막에 두는 이유(위치가 따라온다)만 `[추론]`이다.

## 지은 이름이 없다 — 08과 다른 점

`§3.2`의 기능은 **메뉴명이 처음부터 한글이다**(`객체속성일괄지정`·`객체 위치 고정`·`객체 락`).
08이 `Style Catalog`에 이름을 지어야 했던 것과 반대 상황이라 **이 페이지가 01a에 넘기는 이름
후보는 0개**다. 병기 둘(`Safe Area(안내선)` · `Undo/Redo(작업취소·다시실행)`)도 매뉴얼에서 그대로
왔다.

대신 화면에서 확인할 것이 **메뉴 경로 문자열**이다 — 본문이 `편집 > 객체속성 일괄지정`과
`편집 > 같은 순서의 레이어 객체들에만 현재 속성 적용`을 그대로 적었고, 이건 매뉴얼이 적은
문자열이지 화면을 본 것이 아니다.

## 색 낱말 — 규칙의 경계를 여기서 그었다

본문 규칙 둘째(*"아이콘은 생김새가 아니라 경로로 가리킨다"*)의 근거는 **그 문장이 PDF에서
안 나오기 때문**이다(*"빨간 OnAir 버튼"*). 그래서 **PDF가 직접 적은 색은 다르게 다뤘다** —
이 페이지는 셋을 싣는다: 기준 객체의 `노란색 컨트롤 포인트 8개`(p.27) · 위치 고정된 객체의
`회색 선`(p.30) · 그룹의 `빨간색 점선`(p.29). 전부 **고르는 길이 아니라 화면이 돌려주는
표시**이고, 특히 첫째는 여러 개를 골랐을 때 어느 것이 기준인지 아는 유일한 길이다.

**앞 세 페이지의 테스트에 있던 `빨간|녹색|파란` 금지를 이 페이지에는 안 걸었다.** 처음에는
걸었다가 되돌렸는데, 그대로 두면 **원본이 적은 색은 지우고 원본이 적은 다른 색은 남기는**
자기모순이 생긴다(`빨간색 점선`만 빠지고 `노란색`·`회색`은 남는다). 앞 페이지들의 금지는
그대로 둔다 — 거기서는 실제로 걸릴 색 문장이 PDF에 없다.

가리키는 자리는 전부 경로다. `build-docs.test.ts`가 이 페이지에 **`아이콘`이라는 낱말 자체를
금지**한다 — 원본이 *"메뉴를 체크하거나 icon을 선택한다"*로 적은 자리에서 **메뉴 경로 쪽만**
쓴다. 예외로 보일 만한 자리가 `페이지 리스트 업데이트` 한 줄인데(원본이 아이콘으로만 설명한다),
**이름이 있으므로 2차 강등 조건**(*"경로도 이름도 없는 자리"*)에 안 걸린다 — 08이 텍스트
임포트에서 같은 항목을 같은 방식으로 이미 실었다.

## 인용한 자리 — §3.2는 p.25–31이다

07이 세운 규칙을 그대로 따른다(PDF 쪽 번호 = 인쇄 번호 + 29).

| 절 | 인쇄 번호 |
|---|---|
| §3.2 객체 편집 | p.25–30 |
| §3.2.13의 꼬리 (`Ctrl+U` · `Ctrl+Shift+U`) | **p.31** |

**목차는 §3.2를 6페이지(p.25–30)로 적지만 `3.2.13`의 뒷부분이 p.31로 넘어간다.** 태그는
「그 절」이 아니라 「그 문장이 실제로 있는 쪽」이라 그 셋은 p.31이고, 게이트도 25–31로 가두되
**p.31을 실제로 인용하는지까지 본다**(안 그러면 범위가 느슨하기만 하다).

편집 단축키 표(§7.2, p.107–108)는 **인용하지 않았다.** 이 페이지가 쓰는 단축키가 전부 §3.2
본문에 그대로 적혀 있어서, 같은 사실을 더 먼 쪽에서 끌어올 이유가 없다.

## 08이 올린 규칙을 처음 적용했다

*"한 문장에 두 출처가 섞이면 문장을 쪼개고 태그를 따로 단다."* 초안을 PDF와 문장 단위로
대조하면서 **여섯 자리가 걸렸고 전부 08과 같은 모양이었다** — 원본 사실 옆에 우리 추론이
붙어 한 태그로 묶인 것.

- *"노란색 포인트 8개가 생긴다"*(원본) + *"어느 것이 기준인지 그걸로 안다"*(추론)
- *"조절 상자 8개"*(원본 p.26) + *"숫자로 넣는 쪽은 도형 속성"*(추론)
- *"`Safe Area` 기준"*(원본) + *"화면 가장자리 안쪽 영역"*(추론)
- *"`Ctrl`+드래그는 복사가 된다"*(원본) + *"고르는 데는 `Shift`가 안전하다"*(운영)
- *"체크가 켜진 동안 계속 걸린다"*(원본 p.30) + *"끝나면 끄는 편이 낫다"*(운영)
- 그룹 표 한 줄이 p.28과 p.29 두 쪽에 걸쳐 있었다 — 칸마다 태그를 따로 달았다

덧붙여 **범위를 넓혀 적은 것 셋**을 되돌렸다. 원본이 *"NABI에서 도형, 글자, 이미지의 객체로
이루어지며"*라 적은 것을 **`나비CG의 페이지는`으로 좁혀** 쓴 것(페이지 단위 구성은 원본의
주장이 아니다), *"수직·수평 복사"*에 *"더 빠르다"*를 얹은 것, p.30의 예시(*"2번째 텍스트 객체
레이어"*)를 *"서식이 다른 자막"*으로 바꿔 적은 것.

**코드리뷰가 PDF로 인용 60건을 다시 대조해 쪽 번호 오류 0건을 확인했다** — 08의 사고는
재발하지 않았다. 대신 같은 규칙의 **다른 얼굴** 둘을 더 잡았다: *"고르는 길은 둘이다"*(원본)와
*"겹쳐 있느냐로 갈린다"*(운영)가 한 태그였던 것, 그리고 *"셋이 있고 바뀌는 범위가
다르다"*(원본 p.30)가 **태그 없이** 지나간 것 — 파서가 한 단위의 마지막 문장에만 태그를
붙이므로, 앞 문장의 출처가 다르면 **사이드카에서 통째로 사라진다.**

## 앞 페이지 **셋**의 죽은 참조가 살아났다

07·08은 이 페이지가 없어 `객체 편집`을 **본문에 이름으로만** 적어 뒀다(죽은 링크 금지 게이트).
라우트가 생겼으므로 `text-attributes` · `shape-attributes` · `style-catalog` 세 장의 `H2 관련`이
실제 링크가 됐고, 같은 자리에 있던 `Style Catalog` 참조도 함께 이었다. 게이트가 한 줄 늘었다 —
**앞 페이지가 걸어 둔 참조가 링크인지**까지 본다.

셋째(`style-catalog`)는 처음에 빠뜨렸고 **코드리뷰가 잡았다.** 게이트를 같이 넣었는데도 놓친
이유가 분명하다 — 새 게이트의 루프에 그 슬러그를 안 적었다. **테스트가 목록을 들고 있으면
목록이 곧 사각지대다.**

## 남은 것 — 기준값 블록은 안 생긴다

`_values`도 치환기도 아직 없다(03 미착수). 다만 **이 페이지는 03이 와도 값 블록이 안 생긴다** —
Style Catalog와 같은 이유로, 여기 있는 것은 값이 아니라 **여러 개에 값을 거는 장치**다. 숫자는
글자 속성·도형 속성 쪽에 있고 이 페이지는 그 둘을 링크로 가리킨다.

그래서 열린 칸은 **`01a`의 화면 한글 이름 대조 하나**뿐이다.

## 색인이 292 KB가 됐다 — 이 한 장이 +73 KB다

**실측이다**(이 페이지만 빼고 다시 구웠다): 218.5 KB → 291.6 KB. 지금까지 알려진 값은 *"본문
한 장당 +40 KB"*였는데 **이 장이 그 두 배 가까이 든다.** 단축키 문자열과 표가 많아 2-gram이
겹치지 않는 종류의 본문이다.

스펙 예산은 ~36 KB였고 **게이트가 없어 아무도 안 막는다.** 남은 본문 티켓이 둘(10·11)이고
그중 하나가 **단축키 치트시트**라 같은 성질을 한 번 더 받는다. 이 티켓의 몫은 아니지만 숫자를
여기 남긴다 — 막을 거라면 10 전에 막는 편이 싸다.
