# 04 — 문장별 출처 사이드카 + `[추론]` 인라인 배지

**What to build:** 본문 문장마다 붙은 태그를 `buildDocs()`가 걷어 **사이드카를 산출물로 낸다.**
화면에서는 `[추론]` 문장만 문장 끝에 「확인 전」 배지를 단다. 검수자가 32페이지가 아니라
**수십 줄**을 본다.

**Blocked by:** 02 — 뼈대 (`buildDocs()`가 서 있어야 산출물이 하나 늘어난다).

**Status:** ready-for-agent

## 태그 다섯

| 태그 | 무엇 | 낡는 조건 | 화면 표시 |
|---|---|---|---|
| `[원본 p.NN]` | 매뉴얼이 적은 사실 | 매뉴얼이 갱신되면 — **안 된다** | 없음 |
| `[추론]` | 원본에서 메운 자리 | 화면 확인으로 승격 | **배지 「확인 전」** |
| `[운영 지식 필요]` | 빈 슬롯 | — | (출시 전에 사라짐) |
| `[운영]` | 채워진 우리 값(문장) | 우리 운영이 바뀌면 | 없음 |
| `[화면 YYYY.MM]` | 화면에서 확인한 나비CG 사실 | 프로그램이 바뀌면 | 없음 |

마크다운 문법은 템플릿에 **한 줄로** 명시하고 렌더에서 배지로 바꾼다.

## 사이드카는 상주 산출물이다

검수용 임시물이 아니다. 검수가 끝나도 `[운영]`과 `[화면]`은 남고, 각각 *"우리 운영이 바뀌면
다시 볼 곳"*과 *"프로그램이 바뀌면 다시 볼 곳"*의 인덱스가 된다. **한 파일에서 두 시계가 각자
돈다.** 06의 게이트 5가 이 산출물의 `[화면]` 쪽을 읽는다.

## 화면에 뜨는 것은 하나뿐

`[원본]`은 거의 모든 문장이라 노이즈이고, `[운영 지식 필요]`는 출시 전에 채워지거나 문장 자체가
없으며, `[운영]`·`[화면]`은 신뢰도가 `[원본]`과 동급 이상이다.

- **페이지 상단 배너를 안 만든다** — *"이 페이지에 미확인 3곳"*은 신뢰를 페이지 통째로 깎는다
- **문단 세로선을 안 만든다** — 확인된 문장까지 묶이고, 쓰는 사람이 미확인 문장을 한 문단에
  몰아 쓰게 되어 문장 단위로 쪼갠 이유가 사라진다
- M1의 대가는 시끄러움인데 **줄어드는 종류의 비용**이다. 검수가 진행되면 배지가 하나씩
  사라지고 **0이 정상 상태**다

- [ ] 태그 5종을 문장 끝에 붙이는 마크다운 문법이 템플릿에 한 줄로 명시돼 있다
- [ ] `buildDocs()`가 사이드카를 산출물로 낸다 — 페이지 · 문장 · 태그가 목록으로 나온다
- [ ] `[추론]` 문장만 화면에서 문장 끝 「확인 전」 배지가 된다
- [ ] 나머지 네 태그는 화면에 아무 흔적도 안 남긴다
- [ ] 사이드카에서 `[운영]`과 `[화면]`을 각각 뽑아 볼 수 있다 — 두 시계의 인덱스
- [ ] 페이지 상단 배너와 문단 세로선이 없다
- [ ] 글자 속성 페이지에 태그가 실제로 달려 있고 배지가 화면에 뜬다
- [ ] 태그 파서에 별도 테스트가 없다 — **사이드카 산출물로만** 검증된다
- [ ] 태그가 본문 페이지의 클라이언트 JS를 늘리지 않는다
