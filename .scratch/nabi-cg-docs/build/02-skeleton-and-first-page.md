# 02 — 뼈대: `/docs/nabi-cg/`에 글자 속성 한 장이 뜬다

**What to build:** 브라우저에서 주소를 열면 **왼쪽 사이드바 일곱 줄과 아래 푸터 네 줄을 두른
글자 속성 페이지**가 뜬다. 마크다운 한 장이 소스이고 클라이언트 JS는 안 내려간다.

이 티켓이 `buildDocs()`의 첫 형태를 세운다 — 지금은 **페이지와 내비 둘만** 낸다. 색인은 05가,
사이드카는 04가 같은 함수에 붙인다.

```
_content/*.md  ┐
_values        ├──▶ buildDocs() ──▶ { pages, index, nav, sidecar }
_meta/*        ┘                      ↑02    ↑05    ↑02    ↑04
```

**Blocked by:** None — can start immediately.

01을 안 기다린다. 글자 속성의 용어(`Kerning`·`Width`·`Leading`)는 **매뉴얼 병기 28종에 이미
있는 것들**이라 옵션창을 열기 전에 써도 두 번 쓸 위험이 낮다. 01을 기다려야 하는 것은
한글 이름이 없다고 실측된 용어를 쓰는 페이지들(08·09·10·11)이다.

**Status:** resolved

## 앉을 자리

`app/docs/nabi-cg/` 폴더 하나에 전부 앉고 `_lib`/`_components`/`_content`/`_meta` 밑줄 규약을
그대로 따른다. "폴더 하나 = 경로 하나" 규약이 한 단 깊어질 뿐이다.

- **`/docs` 인덱스를 만들지 않는다** — 항목 1개짜리 목록은 정보가 0이다
- **홈은 카드가 하나 더 붙을 뿐** — `도구`/`문서` 분류 헤딩은 안 생긴다. 셋째가 올 때 가른다
- 의존성은 `react-markdown` + `remark-gfm` 둘만 는다. **문서 프레임워크를 얹지 않는다**
- **MDX를 안 쓴다** — 커스텀 컴포넌트 수요가 0이다(그림 0장, 코드 블록 0개)

## 화면

```
┌────────────┬──────────────────────────────────────────────┐
│ [ 검색   ] │  글자 속성 — 크기·간격·굵기 조절              │
│            │                                              │
│ 텍스트 임포트│  글자를 선택하면 아래쪽 Attributes 탭에 …    │
│  원고 txt를 │                                              │
│  자막으로   │  ## 자막이 한 줄에 안 들어갈 때               │
│ 글자 속성   │  ### 1. Width를 줄인다                       │
│  크기·간격  │  …                                           │
│ 도형 속성   │                                              │
│ 객체 편집   │                                              │

     300px
```

**1단 배열은 흐름 순이다** — 출처는 매뉴얼 챕터 순서가 아니라 작업 목록 13개 중 매일 작업의
실제 순서다. `단축키`는 기능 축에 안 붙으므로 **하위가 아니라 옆에** 단일 페이지로 선다
("기타" 서랍 금지).

**모든 1단 항목에 우리 문장 한 줄**이 붙는다. 이 한 줄이 발견 면 전부이고, 05가 이걸 색인에도
넣는다. `Style Catalog`라는 이름만으로는 그게 뭔지 알 수 없다는 것이 이 한 줄을 산 이유다.

**반응형 전용 설계가 없다.** 좁은 화면에서 한 컬럼으로 접히기만 한다(Tailwind 기본, 공짜).
모바일 내비·터치 타깃·인쇄 CSS·오프라인 전부 없다.

## 푸터 네 줄

```
출처 — compix 나비CG 매뉴얼 기반
기준 — 나비CG 2.5 (2026.02 빌드) · compix 최신 버전은 아래 링크에서 확인
비공식 — compix 공식 문서가 아닙니다
원본 — https://compix.co.kr/posts/3/62?menuId=27
```

- **전 문서 페이지에 붙는다** — 검색으로 딥 페이지에 바로 떨어지므로 홈에만 두면 대부분이 못 본다
- **홈·자막 추출기에는 안 붙인다** — 표기 대상이 매뉴얼에서 온 내용이므로 범위가 그것과 일치해야 한다
- **날짜는 `_meta`의 `NABI_BUILD` 상수에서 읽는다.** 손으로 적으면 상수와 어긋난다
- 페이지 상단 배지는 안 만든다

## 첫 페이지

프로토타입 42(`prototypes/42-글자속성-글로만.md`)를 이식한다. **매뉴얼 사실 부분만** 옮긴다 —
우리 값 블록은 03이, 문장별 태그는 04가 같은 페이지에 얹는다. 기본형 슬롯 다섯을 이 페이지가
먼저 실증한다: `H1 기능 이름 + 해주는 일 한 줄` / `어디서 여는가` / `H2 작업들` /
`H2 나머지 속성`(레퍼런스 표) / `H2 관련`.

프로토타입에 **`자간`이 0회**라는 것이 09가 잡아낸 사고다. 이식하면서 첫 등장 병기
`Kerning(자간)`을 복원한다 — 05의 재현율 게이트가 정확히 이걸 잡으러 온다.

## 남길 결정 하나

**URL 슬러그 규칙.** 스펙이 정해 두지 않았고 이 티켓이 정한다. 제약은 사용자 스토리 13이다 —
*"주소를 북마크하고 **다른 사람에게 불러줄 수 있기를** 원한다."* 인수인계 때 받아 적게 하는
용도이므로 복사했을 때 퍼센트 인코딩으로 터지는지, 입으로 부를 수 있는지 둘 다 본다.

### 결정 — ASCII 소문자·숫자·하이픈, 이름은 화면의 영문을 우선한다

```
/docs/nabi-cg/text-attributes
```

| 슬러그 | 페이지 | 이름의 출처 |
|---|---|---|
| `text-import` | 텍스트 임포트 | 기능의 영문 이름 |
| `text-attributes` | 글자 속성 | 화면 — `Attributes` 탭 |
| `shape-attributes` | 도형 속성 | 화면 — `Attributes` 탭 |
| `object-editing` | 객체 편집 | 기능의 영문 이름 |
| `style-catalog` | Style Catalog | **화면 그대로** |
| `playback` | 송출 | **화면 그대로** — `Playback` |
| `shortcuts` | 단축키 | 기능의 영문 이름 |

**두 잣대 중 복사가 먼저 걸린다.** 한글 슬러그는 `글자속성` → `%EA%B8%80%EC%9E%90%EC%86%8D%EC%84%B1`
(36자)로 부푼다. 브라우저 주소창은 한글로 보여 주지만 **채팅·메모로 옮기는 순간 그 형태로 굳고,**
받아 적는 사람 앞에는 읽을 수도 부를 수도 없는 문자열이 남는다. 되돌릴 방법이 없다.

**부르는 쪽 하중은 딥 페이지에 거의 안 걸린다.** 인수인계 때 받아 적게 하는 주소는 뿌리
하나(`chambitstudio.com/docs/nabi-cg/`)이고 그 아래로는 사이드바 일곱 줄과 검색이 데려간다.
딥 페이지는 불러 주는 것이 아니라 **북마크·복사**되는 것이다 — 두 잣대가 같은 페이지에
동시에 걸리지 않는다.

**슬러그는 검색 키가 아니다.** 진입이 검색이고 색인은 본문·제목·한 줄 설명에서 굽는다.
슬러그에 한글을 밀어 넣어 검색을 도우려는 유인이 애초에 없다.

**이름은 발명하지 않는다.** 나비CG 화면에 영문 이름이 있으면 그것을 쓰고(`style-catalog`·
`playback`), 없을 때만 그 기능의 영문 이름을 쓴다. 화면과 주소가 어긋나면 불러 주는 쪽이
두 이름을 외워야 한다.

**규칙은 주석이 아니라 가드로 선다** — `_lib/build-docs.ts`의 `SLUG`가 빌드에서 강제하고
`buildDocs()` 산출물에 대한 테스트가 `encodeURI(href) === href`를 본다. 이름 짓는 자리가
앞으로 여섯 번 더 오기 때문이다.
