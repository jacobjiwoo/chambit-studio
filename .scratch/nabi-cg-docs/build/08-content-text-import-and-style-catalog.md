# 08 — 본문: 텍스트 임포트 + Style Catalog

**What to build:** 두 페이지가 열린다.

- **텍스트 임포트** (`Ch2 §3.6.5`, 5p) — 원고 txt를 자막으로 들여오는 페이지. **여기서
  물려받은 사람이 자막 추출기가 있다는 사실을 처음 안다.**
- **Style Catalog** (`Ch2 §3.4`, 3p) — 서식을 모아 두고 재사용하는 페이지. **`스타일`로
  검색했을 때 걸리는 페이지가 여기다.**

**Blocked by:** 04 — 사이드카 + 배지 (**충족됨**).

~~01 — 방송실 PC 실측~~ · ~~03 — 값 파일 + 토큰 치환~~ → **07과 같은 방식으로 미룬다.**
07이 값 블록 한 칸을 비운 채 열한 칸 중 열을 닫고 나갔고, 여기도 같다 — 지금 쓰고, 화면 한글
이름 대조와 값 블록은 **열린 칸으로 남겨** 01a·03이 왔을 때 꽂는다. 이름은 우리가 짓되
게이트 1이 절반을 막는다(`스타일` 질의가 하드코딩돼 있어 그 낱말이 본문에 없으면 빌드가
터진다). 틀렸을 때 비용은 find-replace 한 번과 질의 세트 한 줄이다. 근거 전문은 01 §쪼갠 이유.

**Status:** ready-for-human — **본문 두 장은 열렸다.** 열두 항목 중 열이 닫혔고 남은 둘이
`01a`(화면 한글 이름 대조)와 `03`(기준값 블록)의 몫이다. 07과 같은 모양으로 끝난다.

## 두 페이지가 한 티켓인 이유

둘 다 **이름만으로는 뭔지 알 수 없는 기능**이고, 둘 다 `[운영]` 문장이 본문의 핵심이며, 둘 다
01의 한글 이름 판정에 걸린다. 합쳐 8페이지로 한 컨텍스트에 들어간다.

## 자막 추출기를 가리키는 한 줄

`§3.6.5`를 1차로 올린 **유일한 근거**인데 지금까지 문서 어디에도 없었다. 본문 한 줄 +
`/subtitle-extractor` 링크가 들어가고 사이드카 `[운영]`으로 등록된다. **반대 방향(도구 → 문서)은
안 잇는다.**

## `스타일` 질의가 여기 걸린다

검색 시안에서 `스타일` 질의가 **0건**이었고 원인은 색인이 아니라 **본문**이었다 —
`Style Catalog`에 한글 이름이 없어 색인에 한글이 아예 안 들어갔다. 이 페이지가 그 이름을
확정하고, 05의 게이트가 그 순간부터 이 질의를 지킨다.

- [x] 두 페이지 다 기본형 슬롯 다섯을 갖췄다
- [x] 페이지 안쪽 H2가 **작업**으로 갈려 있다
- [x] `Style Catalog`의 한글 이름이 첫 등장 병기로 본문에 있다 — **우리가 짓는다**(`스타일 모음`)
- [x] `Char Unit`도 같은 방식으로 이름이 붙었다 (`Take In`은 11의 몫이다) — `색 적용 단위`
- [ ] **화면 한글 이름 대조 — `01a`로 미룬다.** 화면에 compix가 지어 둔 한글이 있으면 그걸로 갈고 05의 질의 세트를 같이 고친다. 07의 값 블록과 같은 자리이고, **이 칸이 닫히기 전에는 `ready-for-human`이다**
- [ ] **기준값 블록 — `03`으로 미룬다** (§남은 것)
- [x] 텍스트 임포트 본문에 자막 추출기를 가리키는 한 줄과 `/subtitle-extractor` 링크가 있다
- [x] 그 한 줄이 사이드카에 `[운영]`으로 등록돼 있다
- [x] 문장마다 태그가 붙어 있고 `[추론]` 문장에 배지가 뜬다
- [x] 아이콘을 경로로 가리킨다 — 경로도 이름도 없는 자리는 **쓰지 않고 2차로 내린다**
- [x] 그림이 0장이다
- [x] **`스타일` 질의가 Style Catalog 페이지를 반환한다** — 05의 게이트가 통과한다

## 지은 이름 둘 — 01a가 대조할 목록

| 영문 | 우리가 지은 한글 | 어디에 |
|---|---|---|
| `Style Catalog` | **스타일 모음** | `style-catalog.md` 첫 줄 |
| `Char Unit` | **색 적용 단위** | `text-attributes.md` §나머지 속성 |

`Char(글자)` · `Color(색)` · `Shape(도형)` · `Page(페이지)` 넷도 같이 병기했다. **화면에
compix가 지어 둔 한글이 있으면 그쪽이 이긴다** — 그때 고칠 곳은 find-replace 한 번과
`search.test.ts`의 질의 세트 한 줄이다.

**`스타일`이라는 낱말은 매뉴얼이 이미 쓰고 있었다** — `§1.1.8`(p.2)이 Style Catalog를
*"다양한 스타일을 저장하여"*로 설명한다. 지은 것은 `모음`뿐이고, 그래서 게이트 1의 `스타일`
질의는 이름이 뒤집혀도 안 터진다.

## 남은 것 — 기준값 블록

`_values`도 토큰 치환기도 아직 없다(03 미착수). **두 페이지 다 07과 같은 방식으로 값 블록
없이 열었다.**

- **텍스트 임포트** — §1의 서체 기본값(설교 자막 `Height`·`Width`·`Kerning`·`Leading`)이 들어갈
  자리다. 03이 붙는 날 `### 1. 서체와 자리를 먼저 정한다` 아래에 인용 블록 한 개가 들어간다
- **Style Catalog** — 값 12칸에 해당하는 숫자가 **없다.** 이 페이지는 값이 아니라 **값을 저장해
  두는 장치**를 설명하므로 03이 와도 블록이 안 생긴다

본문 문장은 어느 쪽도 손댈 것이 없다.

## 인용한 자리 — 자는 인쇄 번호 하나다

07이 세운 규칙을 그대로 따른다(PDF 쪽 번호 = 인쇄 번호 + 29).

| 페이지 | 인용 구간 |
|---|---|
| 텍스트 임포트 | §3.6.5 텍스트 파일(p.49–53) · §7.4 삽입 단축키(p.110) |
| Style Catalog | §1.1.8 UI구성(p.2) · §3.3.10.4 페이지 템플릿 일괄지정(p.35) · §3.4(p.36–39) · §7.2 편집 단축키(p.109) |

`build-docs.test.ts`가 사이드카의 `원본` 태그를 이 구간들로 가둔다.

**그런데 이 게이트가 잡지 못하는 것을 이번에 확인했다.** 코드리뷰가 PDF를 열어 12건을
대조했더니 **6건이 어긋나 있었고 범위 테스트는 6건 전부를 통과시켰다** — 게이트는 **절을
가둘 뿐 문장을 안 보기 때문**이다. 어긋난 모양은 둘뿐이었다.

- **목록에 항목을 얹었다** — p.2는 *"글자, 색상, 이미지, 동영상"*인데 본문이 `도형·페이지`로
  바꿔 적었다(그 둘은 p.37이다). p.37의 *"Image, Back, Animation처럼"*에 `Video`·`Back Video`를
  더한 것도 같은 사고다
- **사실 옆에 추론을 붙여 한 태그로 묶었다** — *"여덟 영역 중 하나"*는 원본이지만 *"늘 떠
  있다"*는 매뉴얼에 없다. *"원고 한 장이 여러 페이지로 갈린다"*도 p.49가 아니라 p.50이다

여섯 건 다 고쳤고, **규칙 한 줄이 [공통 규칙](README.md)에 올라갔다** — 한 문장에 두 출처가
섞이면 문장을 쪼갠다. 09–11이 같은 자리를 세 번 더 지난다.

## 07의 링크 게이트를 두 번 더 지났다

07이 *"08–11이 같은 자리를 네 번 더 지난다"*고 예고한 자리다. 이번에 건 문서 안 링크는
**두 페이지가 서로를 가리키는 것 둘 + 글자 속성·도형 속성·안내문 넷**이고, 전부 본문이 있는
슬러그다. 여기에 07에 없던 종류가 하나 붙었다 — **`/subtitle-extractor`로 나가는 문서 밖
링크**. 죽은 링크 게이트는 `/docs/nabi-cg`로 시작하는 것만 보므로 이 한 줄은 게이트 밖이고,
대신 그 도구가 이 저장소 안에 있어 라우트가 사라지면 빌드가 먼저 터진다.
