# 05 — 검색: 색인 굽기 + `Ctrl+K` 모달 (게이트 1)

**What to build:** 나비CG 화면에 보이는 단어를 그대로 치면 그 자리로 떨어진다. `Ctrl+K`로
어디서든 열리고 `Esc`로 보던 자리로 돌아간다. **검색을 안 쓰는 방문에서는 JS가 실질 0**이다.

그리고 본문을 쓰다 검색 키를 흘리면 **빌드가 멈춘다** — 이 사이트에서 가장 값이 큰 게이트다.

**Blocked by:** 02 — 뼈대 (색인이 `buildDocs()`의 네 번째 산출물로 붙고, 사이드바에 검색창이
앉는다).

**Status:** resolved

## 토크나이저가 지는 것 셋

의존성은 `minisearch` 하나가 는다. 형태소 경로(`garu-ko` WASM)는 안 간다 — 코퍼스가 조사
코퍼스의 22%(한글 약 7,200자)라 **그 경로의 유일한 근거였던 25 KB 우위가 5 KB로 붕괴한다.**

1. **어절 분해** — 조사는 prefix 확장이 흡수한다 (재현율 60% → 92%)
2. **2-gram** — 복합명사 안쪽을 연다 (→ 100%)
3. **공백 제거 정규화** — 색인을 구울 때 `줄 간격` → `줄간격` 버전도 **함께** 넣는다.
   **2-gram만으로는 띄어쓰기 변형을 못 흡수한다** (어절 경계를 넘는 `줄간`은 색인에 없다)

셋째가 시안에서 실제로 터진 자리다. `줄간격` 질의가 **0건**이었다.

## 화면 — S2 모달

관례를 따랐고 손에 익은 것이 사고 없이 열린다. 대가는 기록해 둔다 — 나비CG와 모니터 한 대를
나눠 쓰는 중이라 **모달이 본문을 덮는다.** 대신 사이드바가 끝까지 발견 전용으로 남아 층위가
화면에서도 안 섞인다.

- 사이드바 검색창은 **정적 HTML**이고, 포커스하거나 `Ctrl+K`를 누르는 **순간에** 색인과 엔진을
  `import()`한다
- 결과 한 줄 = `섹션 › 소제목` + 매치 문맥(하이라이트)
- 포커스 트랩 · 스크롤 잠금 · `aria-modal` · `Esc`로 닫힘
- **초성 검색은 1차 제외.** 순수 추가분이라 나중에 얹어도 문이 안 닫힌다

## 게이트 1 — 질의 20개 재현율 `>= 0.92`

카테고리 결정(1단 트리를 기능 축으로 가른 것)의 **뒤집힐 조건**이 92%다. **테스트가 없으면 그
선을 넘은 것을 아무도 모른다.** 2-gram 실측이 100%이므로 8%p 여유를 두고 지킨다.

**세트에 `줄간격`과 `스타일`을 반드시 넣는다.** 이 둘이 게이트가 잡아야 하는 **두 종류의 대표
표본**이다 — `줄간격`은 **색인 쪽**(공백 제거 정규화가 죽으면 터진다), `스타일`은 **본문
쪽**(`Style Catalog`의 한글 이름을 안 지으면 터진다). 세트는 원본에서 뽑아올 수 없다.
**우리가 지은 한글 이름을 포함해야 한다.**

**본문이 아직 없는 페이지를 겨냥한 질의는 유예한다** — 정답 페이지가 저장소에 생기는 순간
자동으로 게이트에 들어오고, 그때부터 그 질의도 92%를 지켜야 한다. 본문이 늘수록 게이트가
스스로 조여든다.

- [x] 사이드바 검색창이 정적 HTML이고(내보낸 HTML에 그대로 들어 있다), 포커스하거나 `Ctrl+K`를 누르는 순간에만 색인·엔진이 내려온다
- [x] 검색을 안 쓰는 방문에서 본문 페이지의 클라이언트 JS가 여전히 0이다 — **실측 +1,081 B**(§JS 실측)
- [x] 색인이 빌드에서 구워진다 — 어절 · 2-gram · 공백 제거 정규화 셋이 전부 적용된다
- [x] `자간`과 `Kerning` 중 무엇을 쳐도 같은 곳이 나온다
- [x] `줄간격`으로 붙여 쳐도 `줄 간격`이 걸린다
- [x] `Ctrl+H` 같은 단축키 문자열로도 걸린다
- [x] 사이드바 한 줄 설명이 색인에 들어간다
- [x] 결과 한 줄에 `섹션 › 소제목`과 매치 문맥이 뜬다
- [x] `Esc`로 닫히고 보던 자리로 돌아간다
- [x] 포커스 트랩 · 스크롤 잠금 · `aria-modal`
- [x] 질의 20개 세트가 리터럴로 적혀 있고 `줄간격`과 `스타일`이 들어 있다
- [x] 세트에 우리가 지은 한글 이름이 포함돼 있다
- [x] **게이트 1** — 재현율이 0.92 아래로 떨어지면 테스트가 실패한다
- [x] 게이트가 **색인 산출물**에 걸린다 — 토크나이저 내부 자료구조를 보는 테스트가 없다
- [x] 정답 페이지가 아직 없는 질의는 유예되고, 페이지가 생기면 자동으로 게이트에 들어온다
- [x] 초성 검색이 없다

## 구현하며 정한 것 셋

**① 색인은 라우트로 나간다** — `search-index.json/route.ts`(`dynamic = "force-static"`)가
`buildDocs()`의 색인을 그대로 내보내 `out/docs/nabi-cg/search-index.json`이 된다. `public/`에
미리 굽는 길은 빌드 스크립트가 하나 늘고 **생성물이 저장소에 커밋된다** — 본문을 고치고 다시
굽는 것을 잊으면 색인이 조용히 낡는다. 여기서는 그럴 수가 없다.

**② 앵커는 소제목의 해시다**(`#sa4oj90`). 한글 소제목을 `id`로 쓰면 02가 슬러그를 ASCII로
정한 잣대에 그대로 걸린다(복사하는 순간 `#%EC%9E%90…`로 굳는다). 순번(`#s1`)은 섹션을 하나
끼워 넣으면 그 아래가 전부 밀려 **북마크가 조용히 다른 자리를 가리킨다.** 해시는 소제목이
바뀔 때만 바뀌고, 그때는 가리키던 자리가 실제로 없어진 때다. 대가는 주소만 보고는 어느 절인지
알 수 없다는 것.

두 쪽이 나눠 쓰는 것은 **해시 함수(`_lib/anchor.ts`)와 소제목 정규화(`inline()`) 둘**이다.
그래도 해시에 들어가는 글자를 **뽑는 방법**은 다르다 — 색인은 마크다운 원문에서, 화면은
`react-markdown`이 만든 트리에서 뽑는다. 강조·코드·링크는 양쪽이 같은 글자를 내지만,
소제목에 **그림이나 날 HTML**을 넣으면 갈라질 수 있다(둘 다 본문 규칙상 0장·0개다).
갈라지면 검색 결과가 페이지 맨 위에 떨어진다 — 조용한 실패라 여기 적어 둔다.

**③ 질의 쪽에는 공백 제거 정규화를 안 건다.** 비대칭이 의도다 — 질의어를 붙여 버리면
`자간 크기`처럼 본문에서 **떨어져 있는** 두 낱말이 `자간크기`가 되고, 색인에 없는 `간크`를
AND로 요구하다 0건이 된다. 붙여 친 질의(`줄간격`)는 색인 쪽이 이미 붙여 넣어 뒀다.

## JS 실측 — 검색을 안 쓰는 방문

`next build` 산출물에서 본문 페이지가 처음 받는 스크립트 전량을 잰 것이다.

| | 초기 JS(비압축 합계) |
|---|---:|
| 05 이전 | 632,775 B |
| 05 이후 | **633,856 B** (+1,081 B) |

**+1 KB가 문을 여는 조각 전부**다(검색창 · `Ctrl+K` · `import()`). 엔진 `minisearch`는
**따로 선 22 KB 청크**에 있고 색인은 59 KB 파일이며, 둘 다 **검색을 연 순간에만** 내려온다
(헤드리스 Chrome으로 확인 — 안 열면 `search-index.json` 요청이 0건이다). 문자 그대로의 0이
아니라 **실질 0**이고, 그 1 KB 없이는 `Ctrl+K`가 성립하지 않는다.
