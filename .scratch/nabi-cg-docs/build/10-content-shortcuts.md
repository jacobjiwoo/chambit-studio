# 10 — 본문: 단축키 (치트시트형)

**What to build:** `단축키` 페이지가 **표 그대로 한 장**으로 열린다. 훑어 내려가며 찾는
치트시트이므로 쪼개지 않는다. 원본 `Ch2 §7` 전체 5페이지.

**성격을 다시 적어 둔다** — 실측하니 `§7.5 송출`은 **키패드 5개뿐**이고 나머지 전부가
파일·편집·보기·삽입이다. 이건 *"방송 중 치트시트"*가 아니라 **편집 치트시트**다.

**Blocked by:** 01 — 방송실 PC 실측 (누락 단축키 3개의 실제 이름과 동작) · 04 — 사이드카 +
배지 · 06 — 버전 추적 (누락 3개가 `[화면 YYYY.MM]` 태그로 들어가고 게이트 5가 이걸 지킨다).

**Status:** ready-for-human — **본문 한 장은 열렸다.** 여덟 항목 중 여섯이 닫혔고 남은 둘(누락
셋의 `[화면]` 태그와 게이트 5)이 `01b`(방송실 PC)의 몫이다. 07·08·09와 같은 모양으로 끝난다 —
누락 셋은 **빼 두지 않고** compix 변경 이력의 이름으로 표에 올린 뒤 `[추론]` 배지를 달았다.

## 치트시트형은 슬롯이 다르다

기본형이 아니다. **표 그대로**이고 `Icon` 열은 삭제한다 — 30×30 아이콘 24개는 자체 캡처가
원본과 거리를 못 벌어주는 유일한 자산군이라 전부 뺀다.

## 매뉴얼이 짧은 자리

`§7`은 독자가 **전체 목록으로 읽는** 곳이라 **낡음이 가장 위험한 두 자리 중 하나**다. 매뉴얼이
2024-05 이후 갱신되지 않는 동안 소프트웨어가 6번 바뀌었고, 최소 셋이 빠져 있다.

| 단축키 | 출처 |
|---|---|
| `Ctrl+Shift+F5` | Reset Layout |
| `Ctrl+Shift+F9` | Playback Resource Browser |
| `Ctrl+Shift+F8` | File Browser (2026.02, 창 › File Browser) |

셋은 **매뉴얼에 없고 화면에만 있으므로** `[화면 YYYY.MM]` 태그를 단다. 다음에 방송실 PC를
업데이트하면 게이트 5가 이 셋을 터뜨리고 다시 확인하게 만든다.

- [x] 표 한 장이다 — 쪼개지지 않았고 클릭 한 번에 열린다
- [x] `Icon` 열이 없다
- [x] 누락 단축키 3개가 ~~실제~~ 이름·동작과 함께 표에 있다 — **이름은 History의 것이고 화면 확인 전이다**
- [ ] 그 셋에 `[화면 YYYY.MM]` 태그가 붙어 있고 날짜가 `NABI_BUILD`와 같다
- [ ] 게이트 5가 통과한다 — 상수를 올리면 이 셋이 터진다
- [x] `Ctrl+H`로 검색했을 때 이 페이지가 나온다
- [x] 사이드바에서 다른 항목의 하위가 아니라 **같은 층위**에 서 있다
- [x] 그림이 0장이다

## 한 일 (2026-10-30)

`_content/shortcuts.md` 한 장. 원본 `§7` 일곱 갈래(파일 관리 · 편집 · 보기 · 삽입 · 송출 ·

갈래가 소제목이라 검색 결과 줄이 `단축키 › 편집`으로 뜬다. 인쇄 번호는 **p.107–111**이다
(`pdftotext -f 136 -l 140`).

### 누락 셋 — 빼지 않고 `[추론]`으로 올렸다

티켓이 경고한 대로 이 표는 *"이게 전부"*로 읽힌다. `01b`를 기다리며 셋을 빼 두면 그 사이
배포되는 표가 정확히 그 거짓말을 한다. 그래서 `nabi-history.md`의 이름으로 표에 올리고
**`[추론]`(화면에 `확인 전` 배지)** 를 달았다. `01b`가 끝나면 할 일은 셋 —

1. 화면에서 본 이름·동작으로 행을 고친다
2. `[추론]`을 `[화면 2026.02]`(빌드 날짜가 다르면 그 값)로 바꾼다
3. 절 머리의 *"아직 확인하지 않은 줄이다"* 문장을 지운다

테스트는 이 전환을 막지 않는다 — `[추론]`과 `[화면]` 둘 다 받는다.

### §7 표 자체가 짧다 — 매뉴얼 안에서 데려온 둘

매뉴얼 전 쪽에서 단축키 문자열을 긁어 §7 표와 대조했다. 마우스 조합(`Alt+더블클릭` 등)을 빼면
§7에 없는 것은 **`Ctrl+H` / `Ctrl+L`(자간, p.77)** 둘뿐이었다. 글자 폭 옆에 붙이고 태그는
**p.77**을 단다 — 08이 여섯 번 어긴 *"목록에 항목을 얹고 같은 태그로 묶는"* 사고를 피하려고
행마다 태그를 따로 달았다. 티켓의 *"`Ctrl+H`로 검색했을 때 이 페이지가 나온다"* 는 이 두 줄
없이는 성립하지 않았다.

### 매뉴얼이 엇갈리는 자리 둘 — `01b`에 얹었다

- **`Alt+P`가 두 번** — 삽입 `그림 변경`(p.110)과 송출 `프롬프터 송출 On/Off`(p.111)
- **프롬프터 설정** — §7 표는 `Alt+Shift+P`(p.111), 본문 `3.7.4.1` 제목은 `Ctrl+Shift+P`(p.62)

둘 다 화면에서 눌러 봐야 갈린다. [`research/화면-실측.md`](../research/화면-실측.md) §3에 줄을 더했다.

### 걸린 것 하나 — `관련` 절이 `Ctrl+H`를 가로챘다

처음엔 `관련` 줄마다 키를 나열했다(`Ctrl+K`/`Ctrl+J` · `Ctrl+H`/`Ctrl+L` …). 짧은 칸이라
길이 정규화에서 이겨 `Ctrl+H` 1위가 `단축키 › 관련`이 됐고, 05의 *"첫 결과가 Kerning"* 테스트가
터졌다. 키를 빼고 무엇을 하는 페이지인지만 적었다 — 키는 위 표에 이미 있다.
