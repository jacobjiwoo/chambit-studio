# 앉을 자리와 프레임워크

Type: grilling
Status: open
Blocked by: 03, 04

## Question

**이 문서 사이트를 무엇으로 짓고, `chambitstudio.com` 안 어디에 앉힐 것인가.**

**물려받은 것 — 이 맵이 뒤집을 수 있는 대상이다**
- `chambitstudio.com` → Cloudflare Pages, Next.js 16.2 App Router + `output: 'export'` **정적 배포**
- 저장소 public, push하면 자동 배포, Vitest가 빌드 앞에 선다
- 라우팅은 `/` = **도구 목록**, 도구 하나가 폴더 하나(`app/subtitle-extractor/`). 이전 맵이 "공용 디렉터리도, 상태 계층도, `src/`도 만들지 않는다"로 뼈대를 최소로 눌러 뒀다

**갈라야 할 것**

1. **문서가 "도구"인가** — 지금 라우팅은 `/`가 도구 목록이고 도구는 폴더 하나다. 문서 사이트는 읽는 것이지 조작하는 도구가 아니다. `app/nabi-cg-docs/`로 같은 규약에 앉히는가, 아니면 **도구 목록 옆에 다른 성질의 것이 하나 더 서는 구조**를 지금 만드는가. 이전 맵이 "미래 기능을 위한 선제적 설계는 하지 않는다"고 했는데, 이번엔 그 미래가 도착한 경우다
2. **무엇으로 짓는가** — 기존 Next.js 앱 안에 직접 구현 / Nextra·Fumadocs 같은 문서 프레임워크를 같은 앱에 얹기 / 문서만 별도 앱으로 분리. 문서 프레임워크는 사이드바·목차·검색·마크다운을 공짜로 주지만 **기존 앱의 Tailwind v4·App Router·정적 export와 충돌하지 않는지**가 관건이다
3. **검색을 무엇으로 하는가** — [`research/korean-static-search.md`](../research/korean-static-search.md)에 경로 7개와 조합 7개가 총 전송량/재현율/자작량/위험으로 정리돼 있다. **도구 이름이 아니라 그 표를 보고 고를 것.** 반드시 알고 시작해야 할 세 가지:
   - **"한국어 지원"이라 적힌 것을 믿으면 안 된다** — Pagefind는 분절 대상 코드에 `ko`가 없는데 공식 문서는 지원한다고 쓰고 있고, Fumadocs 기본값도 공백 분리다. 아무것도 안 하면 **재현율 60%**
   - **Orama는 지금 고르면 안 된다** — 팀 전원이 이탈해 ZBSearch로 포크(2026-07-08), `@orama/*` 배포 중단. Fumadocs 16.14.0은 이미 옮겼다
   - **프레임워크 내장 검색을 쓰는 것이 곧 한국어를 포기하는 것일 수 있다.** (2)의 "문서 프레임워크가 검색을 공짜로 준다"는 기대가 한국어에서는 성립하지 않는다 — 이 점이 (2)와 (3)의 결합을 바꾼다
4. **URL** — `chambitstudio.com/nabi-cg-docs/...`인가, `/docs/...`인가, 서브도메인인가. 문서 URL은 사람이 북마크하고 서로에게 보내는 것이라 나중에 바꾸기 어렵다
5. ~~**인증이 붙는다면**~~ — **소멸.** `공개 범위`가 **완전 공개, 인증 없음**으로 닫았다(인증은 법적 안전판이 아니라 은폐일 뿐이고, "급할 때 찾아본다"는 목적지의 동사를 해친다). Cloudflare Access도 공개·보호 구역 이음매도 필요 없다 — **물려받은 "인증 없음"이 그대로 유지된다.** 이전 맵의 "로그인은 내부 문서가 붙는 시점에 재검토"는 이행 완료

**`공개 범위`가 추가로 확정한 것 — 이 티켓이 반영해야 할 요구**
- **푸터에 출처 표기 네 줄**(출처 · 기준 버전 나비CG 2.5 · 비공식 문서 명시 · compix 원본 링크)이 **전 페이지에 붙어야 한다.** 문서 사이트는 검색으로 딥 페이지에 바로 떨어지므로 홈에만 두면 대부분이 못 본다 → (2)에서 문서 프레임워크를 고른다면 **레이아웃 푸터를 우리가 제어할 수 있는지**가 요구사항이 된다
- **원본 PDF는 사이트에 두지 않는다** — 링크만. 정적 자산 목록에서 빠진다

**함께 정해야 할 것**
- **저장소를 나눌 것인가** — 문서 본문 + 이미지가 들어오면 저장소 성격이 바뀐다. (`공개 범위`는 저장소를 가르지 않기로 했다 — 작업 자료까지 **전부 커밋**. 따라서 이 축에 걸리는 제약은 없고 순수하게 기술적 판단이다)
- **빌드 시간** — 이미지 수백 장과 검색 인덱스가 빌드에 붙는다. 자동 배포가 여전히 편한가

**판단 기준** — 기존 뼈대를 최소로 눌러 둔 것은 **첫 도구가 요구하는 만큼만 짓겠다**는 결정이었다. 이 티켓이 그 뼈대를 늘려야 한다면, 늘리는 이유가 **지금의 요구**인지 **가정된 미래**인지 구분해서 적을 것.
