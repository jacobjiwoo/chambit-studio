# 05: 검색

Status: resolved
Blocked by: 03

## 무엇을 만드나

담당자가 제목 일부로 **곡 목록**을 찾고, 결과의 곡을 눌러 **셋리스트**에 담거나 뺀다. spec 유저 스토리 1–12.

세부는 [spec](../spec.md)의 "검색 (`_lib`)"과 "화면"의 라이브러리 항목에 있다.

- 검색 로직은 `_lib`의 순수 함수다. 원본 SQL(`title LIKE %q% COLLATE NOCASE LIMIT 50`)과 같은 결과를 낸다. 디바운스 없이 입력할 때마다 거른다.
- 검색은 seam이 아니라 테스트를 요구하지 않는다(사용자 결정).
- 화면: 검색 입력(placeholder "찬양 제목으로 검색"), 결과 수, 결과 목록(제목, "N장", 담김 여부; 행 전체와 추가 버튼 모두 토글), 빈 상태(검색어 없음 / "검색어" 결과 없음), 곡 목록 불러오는 중·실패 표시.
- 스타일 없이 의미 있는 HTML로 쓴다.

**맡는 범위:** [03](03-foundation.md)이 만든 검색 구역 컴포넌트와 그 아래, 검색 `_lib`. 루트와 다른 구역은 고치지 않는다. props가 모자라면 고치지 말고 `## Comments`에 적는다.

개발 중에는 `songs.json`이 없을 수 있다([04](04-song-list-json.md)가 만든다). 작은 임시 JSON을 같은 경로에 두고 확인하되 **커밋하지 않는다**.

## 완료 조건

- [ ] 검색어를 입력하면 대소문자 무시 부분 일치 결과가 곡 목록 순서대로 최대 50곡 나온다
- [ ] 검색어를 비우면 결과도 빈다. 결과가 없으면 입력한 검색어와 함께 안내가 나온다
- [ ] 결과 수가 보이고, 각 결과에 제목·장수·담김 여부가 보인다
- [ ] 결과를 누르면 셋리스트 맨 뒤에 담기고, 다시 누르면 빠진다. 같은 곡이 두 번 담기지 않는다
- [ ] 곡 목록 불러오는 중과 실패가 구분돼 보인다
- [ ] `pnpm build`, `pnpm lint`, `pnpm typecheck`가 통과한다
