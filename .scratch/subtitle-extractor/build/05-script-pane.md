# 05 — 원고 패널 2단 + 상호 하이라이트

**What to build:** 자막 목록 왼쪽에 원고 전문이 나란히 서고, 담당자가 두 패널을 눈으로 대조해
검수한다. 원고의 한 문단을 누르면 그것이 몇 번 자막이 됐는지 오른쪽에서 강조되고, 자막 한 장을
누르면 원고의 그 자리가 강조된다.

**자막만 봐서는 없는 자막을 절대 못 잡는다.** 원고를 나란히 세우는 것이 검수의 본질이며 이게
이 화면의 존재 이유다.

**Blocked by:** 04 — 올린다 → 받는다.

**Status:** resolved — 커밋 `6002bfd`

## 세부

빨간 글자는 원고 패널에서 **원래 색 그대로** 보인다. 한글에서 보던 원고와 같은 모습이어야
대조가 성립한다. (걸러낸 빨강의 취소선 표기와 모르는 색의 물결 밑줄은 06이 얹는다.)

두 패널은 각각 스크롤한다. 원고 뒷부분을 보면서 앞쪽 자막을 확인할 수 있어야 한다.

상호작용 상태(선택된 장)는 그것이 쓰이는 컴포넌트 안에 산다 — `page.tsx`의 문서 상태와 섞지
않는다.

- [x] 왼쪽 원고 전문 · 오른쪽 자막 장의 2단이다
- [x] 원고 패널에서 빨간 글자가 원래 색 그대로 보인다
- [x] 두 패널이 각각 독립적으로 스크롤된다
- [x] 원고 문단을 누르면 그것이 된 자막 장이 오른쪽에서 강조된다
- [x] 자막 장을 누르면 원고의 그 자리가 강조된다
- [x] 자막이 되지 않은 문단을 눌러도 화면이 깨지지 않는다
- [x] 원고가 길어도(문단 100개 이상) 스크롤과 하이라이트가 버벅이지 않는다

## 짓고 나서

**짝을 잇는 끈은 문단이다.** 규칙 층 출력에 `Subtitle.paragraph`를 넣었다 — 규칙 5가 dedupe를
금지하는 이상 **문구로는 어느 문단에서 왔는지 되찾을 수 없고**(실물 원고에 글자까지 같은 두 장이
있다), 걸러낸 것·모르는 색이 이미 문단을 달고 나오므로 모양도 어긋나지 않는다. 화면 사정으로
비튼 것이 아니라 규칙 2("그 문단이 자막 한 장")가 이미 정해 둔 신원이다. 대신 화면이 "어떤
문단이 자막이 되는가"를 **다시 판정하지 않는다** — 규칙이 두 벌이 되면 어긋나는 날 화면은
멀쩡한 얼굴로 엉뚱한 짝을 강조하고, 담당자는 검수했다고 믿은 채 넘어간다.

**강조에 스크롤을 붙였다.** 두 패널이 각각 스크롤하므로 짝이 화면 밖에 있는 것이 예사고, 강조만
하면 담당자 눈에는 아무 일도 일어나지 않는다(스펙 14: "두 패널을 눈으로 따라가지 않아도"). 06의
「원고에서 보기 →」와는 다른 통로이며 노란 깜빡임은 얹지 않았다. **자기가 누른 패널은 건드리지
않는다** — 방금 손댄 자리가 발밑에서 움직이면 어디를 보고 있었는지 잃는다.

**코드 리뷰가 잡은 것 하나** — 같은 장을 다시 누르면 아무 일도 일어나지 않았다. 3번을 누른 뒤
손으로 스크롤해 3번을 밀어냈다면 3번을 다시 누르는 것은 "거기로 다시 데려다 달라"는 뜻인데, 장
번호만 보면 값이 그대로라 이 기능이 있어야 할 바로 그 자리에서 없는 것처럼 굴었다. 선택을
객체째(`Picked`) 들고 클릭마다 새로 만든다.

**프로토타입 타입을 닫았다.** 04가 잠정으로 남긴 `Doc`/`Block`/`Verdict`를 지우고 `ScriptLine`
하나로 갈음했다 — 원고 패널이 문단 하나를 두고 묻는 것은 "이게 몇 번 자막이 됐나" 하나뿐이라
`subtitle: number | null`이면 끝난다. `Verdict`의 네 이름으로 갈라지는 자리는 화면에 없었다.

**실물에서 확인한 것** — 원고 3편이 문단 114·116·133개다. 마지막 체크박스의 "100개 이상"이
예외가 아니라 **평상시**이고, 8·16·19장이 전부 순서대로 1:1로 짝지어졌다.

**확인하지 않은 것 둘.** (1) 화면을 눈으로 보지 않았다 — 이 세션에 브라우저가 없어 2단 레이아웃과
스크롤·강조는 코드와 CSS로만 섰다. `pnpm dev`로 원고를 올려 한 번 볼 것. (2) `useFollow`에는
테스트가 없다 — DOM 스택(jsdom·RTL)이 저장소에 없고, 그것을 들이는 것은 이 티켓 밖이다. 규칙
층과 유도(`toScript`)는 Vitest가 덮는다.
