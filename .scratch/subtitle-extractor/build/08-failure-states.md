# 08 — 잘 안 되는 날

**What to build:** 파일이 거부되거나 자막이 0장인 날, 담당자가 **무엇을 해야 하는지** 알고
화면에서 빠져나온다. 실패 · 빈 결과 · 정상 셋이 서로 다른 톤으로 갈려서 급한 일과 급하지 않은
일이 즉시 구분된다.

**Blocked by:** 04 — 올린다 → 받는다. (거부 사유 구분과 빈 결과 구분은 03의 파서가 이미 내놓고
있다. 이 티켓은 그것을 화면에 세운다.)

**Status:** ready-for-agent

## 거부 — 사유별로 다른 안내

| 사유 | 안내의 성격 |
|---|---|
| hwp가 아님 (확장자만 `.hwp`인 경우 포함) | 목사님께 받은 한글 원고를 그대로 올려 달라 |
| 암호 설정 | 한글에서 암호를 풀고 다시 저장한 뒤 올려 달라 |
| 배포용 문서 | 무엇을 고쳐야 하는지 |
| DRM 보안 | 무엇을 고쳐야 하는지 |
| 파싱이 깨짐 | 그날은 손으로 한다는 선택지가 있음을 안다 |

거부 화면은 **다음 행동**을 준다. 막힌 채로 끝나면 안 된다.

## 빈 결과 — 오류가 아니다

빨간 글자가 하나도 없는 원고는 파싱이 성공했고 자막이 0장인 것이다. 실패와 **다른 톤**(빨강이
아니라 노랑)으로, **"원고는 정상적으로 열렸습니다"를 먼저** 말한다. 그래야 문제가 파일이 아니라
원고의 색 표시에 있음을 알고, 앱이 고장난 줄 알고 손으로 돌아가지 않는다.

## 어느 화면에서든 빠져나온다

거부 화면 · 빈 결과 화면 어디에서든 다른 파일을 다시 올릴 수 있다.

- [ ] 확장자가 `.hwp`가 아닌 파일이 명확히 거부된다
- [ ] **확장자만 `.hwp`인 파일**도 내용 판정으로 걸러진다 (메신저가 파일명을 뭉갠 경우)
- [ ] 암호 · 배포용 · DRM이 **서로 다른 문구**로 안내된다
- [ ] 각 거부 화면이 다음 행동을 준다
- [ ] 빈 결과가 실패와 다른 톤이고, "원고는 정상적으로 열렸습니다"를 먼저 말한다
- [ ] 실패 · 빈 결과 · 정상 셋이 톤으로 구분된다
- [ ] 거부 화면과 빈 결과 화면 양쪽에서 다른 파일을 다시 올릴 수 있다
