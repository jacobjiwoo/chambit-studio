# 08 — 잘 안 되는 날

**What to build:** 파일이 거부되거나 자막이 0장인 날, 담당자가 **무엇을 해야 하는지** 알고
화면에서 빠져나온다. 실패 · 빈 결과 · 정상 셋이 서로 다른 톤으로 갈려서 급한 일과 급하지 않은
일이 즉시 구분된다.

**Blocked by:** 04 — 올린다 → 받는다. (거부 사유 구분과 빈 결과 구분은 03의 파서가 이미 내놓고
있다. 이 티켓은 그것을 화면에 세운다.)

**Status:** resolved — 커밋 `2270069`

## 거부 — 사유별로 다른 안내

| 사유 | 안내의 성격 |
|---|---|
| hwp가 아님 (확장자만 `.hwp`인 경우 포함) | 목사님께 받은 한글 원고를 그대로 올려 달라 |
| 암호 설정 | 한글에서 암호를 풀고 다시 저장한 뒤 올려 달라 |
| 배포용 문서 | 무엇을 고쳐야 하는지 |
| DRM 보안 | 무엇을 고쳐야 하는지 |
| 파싱이 깨짐 | 그날은 손으로 한다는 선택지가 있음을 안다 |

거부 화면은 **다음 행동**을 준다. 막힌 채로 끝나면 안 된다.

## 빈 결과 — 오류가 아니다

빨간 글자가 하나도 없는 원고는 파싱이 성공했고 자막이 0장인 것이다. 실패와 **다른 톤**(빨강이
아니라 노랑)으로, **"원고는 정상적으로 열렸습니다"를 먼저** 말한다. 그래야 문제가 파일이 아니라
원고의 색 표시에 있음을 알고, 앱이 고장난 줄 알고 손으로 돌아가지 않는다.

## 어느 화면에서든 빠져나온다

거부 화면 · 빈 결과 화면 어디에서든 다른 파일을 다시 올릴 수 있다.

- [x] 확장자가 `.hwp`가 아닌 파일이 명확히 거부된다
- [x] **확장자만 `.hwp`인 파일**도 내용 판정으로 걸러진다 (메신저가 파일명을 뭉갠 경우)
- [x] 암호 · 배포용 · DRM이 **서로 다른 문구**로 안내된다
- [x] 각 거부 화면이 다음 행동을 준다
- [x] 빈 결과가 실패와 다른 톤이고, "원고는 정상적으로 열렸습니다"를 먼저 말한다
- [x] 실패 · 빈 결과 · 정상 셋이 톤으로 구분된다
- [x] 거부 화면과 빈 결과 화면 양쪽에서 다른 파일을 다시 올릴 수 있다

## 짓고 나서

**문구와 톤을 화면에서 뺐다.** 둘 다 `_lib/guidance.ts`가 파서·규칙 층의 출력에서 유도한다.
이유가 둘이다. 하나, **사유별로 다른 말이 나오는지는 눈으로 확인할 수 없다** — 다섯 화면을
나란히 띄울 수 없고, 어느 화면이든 문장이 있긴 하므로 잘못된 안내도 그럴듯해 보인다. 문구가
순수 함수 뒤에 서면 다섯이 정말 다른지 테스트가 한 번에 본다. 둘, 톤을 화면이 따로 고르면
거부를 노랑으로 칠하는 날이 오고, 그날 급한 일과 급하지 않은 일이 섞인다. `Guidance`가 톤을
함께 들고 다니므로 `notice.tsx`가 정하는 것은 **그 톤이 어떻게 보이는지**뿐이다.

**빈 결과의 원인을 규칙 층에게 물었다.** 처음에는 `subtitles.length === 0`을 전부 "빨간 글자가
한 곳도 없습니다"로 답했는데, 코드 리뷰 두 축이 각자 같은 자리를 짚었다 — 검은 글 사이에 낀
빨강만 있는 원고(규칙 2로 전부 `dropped`)에서 그 말은 **거짓말**이다. 눈앞에 빨간 글자가 보이는
담당자는 안내와 원고가 어긋나 앱을 믿지 못하고, 정작 고쳐야 할 것(문단째 칠하기)은 끝내 듣지
못한다. 게다가 이 화면에는 칩 한 줄이 없으므로 06이 세운 노출 의무가 여기서만 사라진다.
그래서 `emptyGuidance`가 추출 결과를 통째로 받아 원인 셋을 갈라 말한다.

**거부 사유를 원고 없이 덮었다.** `corpus.test.ts`는 원고가 있을 때만 돌고, 있어도 원고 3편이
전부 멀쩡한 파일이라 거부가 한 번도 나오지 않는다. `hwp.test.ts`가 `.hwp`를 **손으로 지어서**
넣는다 — 우리가 읽는 것이 스트림 2개와 레코드 3종뿐이라 지을 수 있고, 지어 보는 것 자체가
파서가 읽는 구조를 코드에 박아 둔다. 온전한 원고 하나를 대조군으로 함께 두었다. 그것이 없으면
파서가 무엇이든 거부하도록 망가져도 거부 테스트 전부가 초록으로 남는다.

**이 화면들을 브라우저에서 눈으로 보지 않았다.** 이 저장소에 브라우저 자동화가 없다. 톤이
갈리는지는 데이터 층에서 테스트로 고정했고(거부는 전부 `red`, 빈 결과는 `amber`), 화면은 그
톤을 `TONE`에서 한 번 찾아 쓸 뿐이다. 실제 색과 여백은 `pnpm dev`로 확인해야 한다.
