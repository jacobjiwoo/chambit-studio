# 07 — 미리보기 모달

**What to build:** 받기 전에 **파일에 들어갈 원문 그대로**를 띄운다. 자막 목록은 장 단위로 끊어
보여줄 뿐 나비CG가 실제로 읽을 모습과 생김새가 다르므로, 마지막 확인은 원문으로 한다.

**Blocked by:** 04 — 올린다 → 받는다.

**Status:** resolved — 커밋 `29386c3`

## 세부

미리보기 버튼은 받기 버튼 **옆**에 있다. 모달 본문은 자막 장이 **빈 줄로 갈리는 것을 눈으로
볼 수 있어야** 한다 — 나비CG의 페이지 구분이 제대로 될지 미리 아는 통로다.

푸터에 `UTF-8 BOM · CRLF · 자막 N장 · 장 구분은 빈 줄`. 손으로 맞추던 형식이 제대로 들어갔는지
여기서 확인한다.

**모달 안에서 바로 받을 수 있다.** 확인한 뒤 모달을 닫고 버튼을 다시 찾는 걸음이 생기면 안 된다.

모달 열림 상태는 그것이 쓰이는 컴포넌트 안에 산다.

- [x] 미리보기 버튼이 받기 버튼 옆에 있다
- [x] 모달이 파일에 들어갈 원문 그대로를 보여준다 (장 단위로 끊은 목록이 아니다)
- [x] 자막 장 사이의 빈 줄이 눈에 보인다
- [x] 푸터에 인코딩 · 개행 · 자막 장 수 · 장 구분 방식이 쓰여 있다
- [x] 모달 안의 받기 버튼이 헤더의 받기와 완전히 같은 파일을 떨군다
- [x] 자막이 긴 원고(19장)에서도 모달 안이 스크롤되고 화면을 넘치지 않는다

## 짓고 나서

**장을 이어 붙이는 자리를 하나로 모았다.** 모달이 `subtitles.join("\n\n")`로 제 원문을 짓고
있었다 — 프로토타입에서 옮겨 온 채 아무 데서도 렌더링되지 않던 코드다. 규격을 아는 자리가
둘이면 규격이 바뀌는 날 미리보기만 옛 모습으로 남고, **받기 전 마지막 확인이 파일과 다른
것을 보여주면 그것은 확인이 아니다.** `toNabiBody`가 본문을 내고 `toNabiTxt`가 그 앞에 BOM을
세운다. 매임은 테스트가 잡는다 — 미리보기가 띄우는 글 == 파일에서 BOM을 뗀 것.

실제로 이 갈래가 살아 있었다: 파일은 CRLF인데 모달은 LF로 이어 붙이고 있었다. 눈에 같아
보이는 것이 같은 것이 아니다.

**받기 통로도 하나다.** 헤더의 버튼과 모달 안의 버튼이 **문자 그대로 같은 함수**를 받으므로
"완전히 같은 파일"이 관찰이 아니라 구조다. 그래도 실물 원고 3편으로 두 파일을 받아 바이트
비교했다 — 8장 · 16장 · 19장 전부 동일.

**CRLF를 `<pre>`에 그대로 흘렸다.** 브라우저가 CRLF를 줄바꿈 하나로 접는다는 데 기대는
자리라 실물로 확인했다: 19장 원고에서 CRLF 36개(= (19-1)×2)가 빈 줄 18개로 보인다. 두 줄로
갈리지 않는다.

**모달이 화면을 넘치지 않는 것은 `min-h-0` 하나에 달려 있다.** flex 항목의 최소 높이가 내용
높이라, 이것이 없으면 19장 원고에서 모달이 화면 밖으로 자라고 본문은 스크롤하지 않는다.
1440×900과 1280×620 두 크기 · 원고 3편에서 모달 높이가 뷰포트 안에 들고 문서에 가로세로
스크롤이 생기지 않음을 확인했다.

**코드 리뷰가 잡은 것.** ① 새 함수를 끼워 넣으면서 파일 규격을 적은 주석 덩어리가 `toNabiTxt`
에서 떨어져 나가 BOM도 파일도 만들지 않는 함수를 설명하게 됐다. ② `useMemo`/`useCallback`을
둘렀는데 받는 쪽(`Header`·`PreviewModal`) 어느 것도 `memo`가 아니라 사는 게 없었다 — 이 저장소가
메모이제이션을 두르는 이유는 `memo`한 자식에게 넘기기 때문이다. ③ `role="dialog"`가 패널이 아니라
**배경**에 붙어 화면 전체가 대화상자로 읽혔다. ④ `truncate`는 `min-w-0` 없이는 flex 항목에서
듣지 않아 긴 파일명이 닫기 버튼을 밀어낸다.

**티켓 밖에서 더한 것 — Esc로 닫기.** 확인만 하고 나가는 것이 이 모달의 흔한 끝인데 그 길이
마우스로 ✕를 겨누는 것뿐이면 방송 직전에 열어 본 사람에게는 그것도 한 걸음이다.
