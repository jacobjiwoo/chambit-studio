# 09 — 배포

**What to build:** 담당자가 방송실 PC에서 짧은 주소를 열면 도구가 뜬다. `main`에 push하면
자동으로 배포되고, Vitest가 빌드 앞에 서서 규칙 층 사고가 배포까지 가지 않는다.

**Blocked by:** 04 — 올린다 → 받는다. (「올린다 → 받는다」가 돌아가는 순간 실전 투입이 가능하다.
05~08은 배포된 앱 위로 얹힌다. 도메인 구매·전파 리드타임도 일찍 시작되는 편이 낫다.)

**Status:** ready-for-human — 도메인 결제와 Cloudflare 대시보드 연결은 사람 손이 필요하다.
`output: 'export'`는 01에서 이미 켜져 있고, 테스트 스크립트 순서는 에이전트가 할 수 있다.

## 결정된 값

| 항목 | 결정 |
|---|---|
| 주소 | `chambitstudio.com` — 개인 명의·개인 카드, **자동갱신 ON + 등록 연수 최대** |
| 호스트 | **Cloudflare Pages** 무료 플랜 |
| 저장소 | `jacobjiwoo/chambit-studio`, **public** |
| 트리거 | `main`에 push → CF가 빌드·배포 |
| 순서 | Vitest가 빌드 앞에 선다 |

**자동갱신과 다년 등록은 협상 대상이 아니다.** 매일 예배에 걸린 도구라 도메인 만료 같은 조용한
고장이 곧 사고다.

**결제 화면에서 확인할 값 둘** — 실제 다년 등록 가능 연수, CF Registrar가 `.com` 신규 등록을
받는지(받지 않으면 아무 등록기관에서 사서 CF로 네임서버만 넘긴다). 둘 다 결정을 바꾸지 않는
실행 세부다.

## 만들지 않는 것

스테이징 환경 · 모니터링 · 커스텀 CI 파이프라인. 도구 하나와 개발자 1명이 요구하지 않는다.
브랜치 프리뷰 URL은 CF Pages가 자동으로 만드는 것이므로 **없애려고 손대지 않는다.**

## 공개 전 마지막 확인

저장소가 public이 되는 순간 원고 유출은 "되돌리기 어렵다"에서 **"불가능하다"**로 바뀐다 —
fork·검색 인덱스·캐시가 남는다. push 전에 커밋 히스토리 전체를 한 번 더 본다.

- [ ] `chambitstudio.com`을 자동갱신 ON · 등록 연수 최대로 확보했다
- [x] GitHub `jacobjiwoo/chambit-studio` public 저장소에 push돼 있다
- [x] push 전에 **커밋 히스토리 전체**에 설교 원고 전문(`.hwp`, `fixtures.json`)이 없음을
      확인했다 — 첫 커밋뿐 아니라 모든 커밋
- [ ] Cloudflare Pages가 저장소에 연결돼 `main` push에 빌드·배포된다
- [ ] 빌드 명령이 **테스트를 먼저 돌리고** 실패하면 배포되지 않는다
- [ ] `chambitstudio.com`이 CF Pages를 가리키고 HTTPS로 열린다
- [ ] 방송실 PC의 Edge/Chrome에서 설치 없이 열리고, 실제 `.hwp`로 올린다 → 받는다가 동작한다

## 공개하며 확인한 것

**커밋 17개 전체에 `.hwp`·`fixtures/`가 한 번도 등장한 적 없다.** 첫 커밋부터 그렇고, 원격
트리(76개)에도 없음을 push 뒤에 다시 확인했다.

원고에서 온 **문장 조각**은 테스트와 `issues/04-red-text-rules.md`에 남아 있고, 보고 나서
그대로 두기로 했다. 대부분 성경 구절(고전 1:18·9:12, 잠 4:6~8)과 공개된 어록(허브 브룩스)이며,
목사님이 직접 쓰신 문장은 다섯 개뿐이고 그중 둘은 이미 `…`로 잘려 있다. 이어지는 대목이 한
군데도 없어 설교를 복원할 수 없다 — 티켓이 막으려던 "원고 전문"과 성격이 다르다.

`corpus.test.ts`의 파일명 상수는 **로컬 `fixtures/`의 실제 파일명이어야** 원고를 찾는다.
설교 제목과 날짜가 드러나지만, 바꾸면 이 컴퓨터에서만 아는 이름이 되어 원고를 새로 받을 때마다
손이 간다. 그 값을 치를 만한 위험이 아니라고 봤다.
