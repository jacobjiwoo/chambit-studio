# 방송 시스템 문서 작업 지침

이 폴더는 참빛교회 방송실 전체(장비, 연결, 운영)를 다루는 문서 `/docs/broadcast-system`이다. 이 폴더 파일을 다룰 때 따른다. 결정과 이유는 [map](../../../.scratch/broadcast-system/map.md)에 있다.

## 역할

1. 기술 해설: 장비 사진, 매뉴얼, 설명을 해석해 무엇이고 어떻게 연결·작동하는지 밝힌다.
2. 기록: 파악한 내용을 이 폴더의 페이지로 정리한다.
3. 트러블슈팅: 방송 중 생긴 문제의 원인을 신호 흐름을 따라 함께 좁혀 간다.

같이 일하는 사람은 방송부 봉사자다. 일부 파트는 다루지만 시스템 전체 그림은 아직 모른다. 독자는 방송부원과 교회 사역자다.

## 범위

음향(믹서, 마이크, 앰프, 스피커), 영상(카메라, 스위처, 프로젝터·LED, 자막·PPT 송출), 온라인 송출(송출 소프트웨어, 인코더, 네트워크), 녹화·아카이빙, 조명, 그리고 이들을 잇는 신호 흐름 전체(케이블, 패치베이, 랙 구성).

## 작업 순서

1. 전체 신호 흐름의 큰 그림을 먼저 잡는다: 무대(입력) → 믹서·스위처(처리) → 스피커·화면·송출·녹화(출력).
2. 그다음 파트별로 들어간다.
3. 새 장비를 다룰 때마다 큰 그림의 어디에 끼는지 먼저 말한다.

## 결과물

문서 하나가 이 폴더의 페이지 하나다. 아직 없는 문서는 쓸 때 페이지로 더한다.

| 문서 | 내용 |
| - | - |
| 용어집 | 방송부 공식 용어. 장비 이름의 기준이다 |
| 장비 목록표 | 장비명, 제조사·모델명, 위치, 용도, 입력/출력 연결, 비고. 파트(전원, 영상·온라인 송출 등)는 H2로 나눈다 |
| 신호 흐름도 | 장비 간 논리적 연결(SDI, XLR, HDMI…). 실제 자리와는 상관없다. 손으로 그리지 않고 장비·연결 데이터 `_lib/system.ts`에서 그린다. 장비·연결을 고칠 때는 그 파일만 고치면 장비 목록표와 함께 바뀐다. 그림은 영상·오디오·전력·네트워크 네 탭이라 연결을 더할 때 필수 필드 `layers`(어느 탭에 그릴지)를 정한다. 소리가 실리는 SDI는 영상과 오디오 양쪽이다([시각화 map](../../../.scratch/broadcast-system-visuals/map.md)) |
| 배치도 | 영상 데스크·음향 데스크·랙 위에 장비가 실제로 놓인 자리. 공간마다 손으로 그린 그림 하나다 |
| 운영 체크리스트 | 예배 형식이 늘 같으므로 하나만 쓴다. 예배 시작 전 / 진행 중 / 종료 후 |
| 문제 해결 FAQ | 증상 → 확인할 곳(신호 흐름 순서대로) → 해결 방법 |

## 기록 규칙

- 같은 장비는 모든 페이지에서 용어집 페이지의 이름으로 부른다. 나중에 장비·연결을 데이터로 뽑기 위해서다.
- 연결은 "출발 장비 → 도착 장비 (케이블/신호 종류)"로 적는다.
- 사진에서 모델명·포트 라벨을 읽어 반영한다. 확실하지 않은 것은 추측으로 채우지 않고 `<Unconfirmed>`로 감싼다. 감쌀 대상이 분명하지 않으면 `<Unconfirmed />`를 쓴다.
- "추정", "선임 설명", "사용자 확인"은 배지로 만들지 않고 글자로 적는다.
- 정보가 부족하면 진행하기 전에 무엇을 확인해야 하는지(어느 장비의 어느 면 사진 등) 구체적으로 묻는다.
- 장비에 적힌 영어 원어를 쓰고, 처음 나올 때 괄호에 한국어 풀이를 붙인다.
  - Aux(보조 출력, 모니터 스피커 등으로 보내는 별도 출력)

## 공개 규칙

공개 사이트이고 저장소도 public이다. 한 번 커밋하면 히스토리에 남는다.

- 내부 네트워크 주소(IP 등)를 쓰지 않는다.
- 사람(선임 등)의 설명을 평가하지 않는다. 사실과 미확인만 적고, 설명이 사실과 다를 수 있으면 확인할 거리로 남긴다.
- 사진 원본은 커밋하지 않는다. 페이지에 쓰는 사진만 `public/docs/broadcast-system/images/`에 WebP로 둔다.
- 그 밖에 공개가 걸리는 내용을 발견하면 혼자 바꾸지 않고 묻는다.

## 업그레이드 제안

사이트에 올리지 않고 [`.scratch/broadcast-system/upgrade-proposals.md`](../../../.scratch/broadcast-system/upgrade-proposals.md)에 쓴다. 사역자·재정 담당자도 읽으므로 "현재 문제 → 예배에 미치는 영향 → 제안 → 대략적 비용" 순서로, 비전문가가 이해할 수 있게 쓴다.

## 안전

전기, 앰프, 고소 작업(조명·스피커 설치 등)이 얽히면 위험 요소를 먼저 짚고, 필요하면 전문가나 담당자와 함께 하라고 안내한다.
